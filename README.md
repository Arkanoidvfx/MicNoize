# Mic Noize

Windows 11 x64: **Rust / Iced 0.14 UI + C++20 аудиодвижок**. Личная локальная сборка: NVIDIA-шумоподавление микрофона, локальные голосовые модификаторы, опциональный RVC, постоянный виртуальный микрофон для Discord и игр.

**Последний релиз:** [страница последнего релиза](https://github.com/Arkanoidvfx/MicNoize/releases/latest).

**QuadCast S → NVIDIA Denoiser → RVC (опционально) → модификаторы → boost → TAG → Discord / игры.**

История изменений и результаты всех проверок — в [CHANGELOG.md](CHANGELOG.md). Для нового чата Codex/Claude открывайте эту папку: правила — в [AGENTS.md](AGENTS.md), карта кода и рабочий процесс — в [скилле micnoize](.agents/skills/micnoize/SKILL.md).

## Компоненты

- NVIDIA Audio Effects SDK **3.0.0.51**, Denoiser **3.0.0.0**, 48 кГц v1/v2. Модели TensorRT собраны под архитектуру GPU: движок определяет видеокарту через `nvcuda.dll` (compute capability устройства CUDA 0) и берёт `models/turing|ampere|ada|blackwell`; core содержит только Ampere, модели другой архитектуры UI докачивает отдельным подписанным компонентом `runtime-models-v3.0.0/models-<arch>.json` вместе с core (автостарт ждёт). Если NVIDIA недоступна (не RTX, AMD/Intel, нет модели, `NvAFX_Load` не прошёл), движок включает **DeepFilterNet 3 на процессоре** (MIT/Apache-2.0, модель встроена в `MicNoize.exe`, `ui/src/cpu_denoise.rs`): кадры 480 сэмплов 48 кГц, **+30 мс** задержки (замер корреляцией: 1440 сэмплов), около 0,2–0,3 мс на 10-мс блок на Ryzen 7 7800X3D. Каждый кадр проходит всю модель: пороги libDF по умолчанию (ниже −10 дБ оценки SNR кадр обнуляется, выше 20/30 дБ стадии пропускаются) рвали голос на шумном USB-микрофоне; подавление делают плавные маски самой модели. Поток DSP в этом режиме сбрасывает денормалы (FTZ/DAZ). **GTX 10xx:** SDK требует RTX, но старый RTX Voice (0.5.x, ставится на GTX правкой установщика) работает и на Pascal; выберите его «Микрофон (NVIDIA RTX Voice)» входом Mic Noize. Если имя входа содержит «RTX Voice» или «NVIDIA Broadcast», движок свой шумодав не запускает (ни NVIDIA, ни DFN, без +30 мс): состояние `4`, `denoiser=input` в `sessions.log`, под регуляторами «Шум уже убран на входе»; силу подавления задаёт RTX Voice. Регуляторы шумоподавления работают как предел ослабления: 100–200 % — полное, ниже — 40 дБ × сила, минимум 0,5 дБ (ровно 0 дБ модель пропускает без задержки, и хоткей «при удержании» сдвигал бы звук). Под регуляторами показано «Шумодав DeepFilterNet на процессоре» и причина, почему не NVIDIA. Если и DFN не создаётся (например, в нативных проверках без Rust), голос идёт **без шумодава**, а причина показана оранжевым. Голос, RVC, эффекты, саундпад, TAG/WASAPI и Mute работают во всех режимах. Состояние: C ABI `mnr_denoiser_state` (1 NVIDIA, 2 без шумодава, 3 CPU), `denoiser=nvidia|bypass|cpu` в `sessions.log`, строка в `app.log`. `MNR_DENOISER=cpu` принудительно включает CPU и на RTX (проверки, свободная видеокарта в играх). Приложение регистрирует DFN в движке через `mnr_set_cpu_denoiser`, поэтому нативные проверки собираются без Rust. Цена: `MicNoize.exe` вырос с ~11 до ~34 МБ (tract + модель 8 МБ). Наушники с галкой «Шумодав NVIDIA» по-прежнему требуют NVIDIA. Программа не запускает Broadcast; runtime и модели NVIDIA не изменены, SHA-256 в `nvidia-assets.sha256`. v2 экспериментальная: равенство или превосходство качества над Broadcast не заявляется. Speaker Focus исключён.
- Thin Audio Gateway (TAG) 2.0.0.1903 demo — подписанный Microsoft виртуальный аудиодрайвер; `mic_tag_host.exe` держит его открытым постоянно.
- Rubber Band 4.0.0 LiveShifter — тон, форманты и AutoTune без изменения темпа.
- VCClient 2.1.4-alpha (w-okada/voice-changer) — RVC-сервер как отдельный процесс, REST на `127.0.0.1:18889`.
- VB-CABLE текущим приложением не используется (удалён 2026-09-18); Voicemeeter поддерживается как альтернативный виртуальный выход.

## Установка и обновления

Автозапуск восстановления обновления управляется напрямую через Windows API. Ошибки раннего запуска в `Logs/rust-ui-error.log` содержат этап (сохранение предыдущей установки, восстановление или инициализация); ошибки открытия пакетов и копирования файлов восстановления указывают пути.

Повторные запросы запуска хоста сохраняют активное поколение восстановления, пока Планировщик запускает supervisor/worker. После проверки подписанного комплекта отдельная переустановка через Setup штатно останавливает собственный старый хост и проверяет готовность нового перед завершением старого журнала. При неудаче в app.log сохраняется причина до отката.

Если переустановка через Setup оставила старый журнал обновления, текущая версия проверяется по подписанному полному пакету. Пакет ищется по версии независимо от имени в кэше; при его отсутствии скачивается из официального релиза и сохраняется только после проверки подписи и совпадения установленных UI/хоста. Проверенная подпись также сохраняется. Для восстановления пустого кэша нужен интернет; старый журнал и пакеты отката сохраняются.

При ошибке до открытия окна установленная версия автоматически отправляет разработчику диагностический отчёт: ошибку, ограниченные хвосты логов, пути и наличие файлов, фазу журнала обновления. Отправка ограничена 3 секундами; её результат сохраняется в `Logs/startup-report.log` и показывается в окне ошибки вместе с путём локального лога. Без сети ошибка и лог остаются доступны.

Начиная с 0.2.9, перед загрузкой новой версии полный пакет установленной версии проверяется и сохраняется в `%APPDATA%\Mic Noize\Components\.update`. Velopack очищает старые пакеты в `packages` после загрузки; сохранённая копия остаётся доступной для безопасного отката. Уже выпущенная 0.2.8 не содержит этого исправления: если при её установке из 0.2.7 показана ошибка о предыдущем полном пакете, нужен опубликованный полный пакет 0.2.7 в `%LOCALAPPDATA%\MicNoize\packages`.

**Переход с 0.2.8.** Если после скачивания новой версии старая программа сообщает, что предыдущий полный пакет отсутствует, запустите `Repair-0.2.8-update.ps1` из релиза 0.2.10 (для перехода именно на 0.2.9 — `Repair-0.2.8-to-0.2.9.ps1` из релиза 0.2.9) и снова нажмите «Обновить сейчас». Скрипт скачивает только официальный полный пакет 0.2.8, сверяет его SHA-256 и кладёт в `packages` для отката; установленную программу и виртуальное устройство он не меняет. Если ошибка не появилась, скрипт не нужен. Начиная с 0.2.9 программа сохраняет свой пакет перед скачиванием следующего обновления.

**Патч 0.2.7.** Для перехода с опубликованной 0.2.5 используйте `MicNoize-Upgrade-0.2.7.zip`: после полного выхода из трея `MicNoizeUpgrade.exe` сохраняет старый пакет/core-хост и регистрирует восстановление до замены программы. Перенос линий требует явного подтверждения. Новый канал `win-x64-stable-v2` исключает применение этого пакета старым автоматическим обновлятором; обычный Setup предназначен для новой установки. Переход на копии настоящего пакета 0.2.5 с работающим старым хостом и откат несовместимого кандидата проверены. Запуск старого UI разрешён только после проверки сохранённого core-хоста и его точной линии. Поддерживается только проверенный хеш опубликованного core; неизвестный хост, неоднозначная линия или линия, которую старая версия удалит, требуют действия пользователя. Такой отказ не считается успешно завершённым откатом. При утрате всей папки `current` восстановление возвращает метаданные из проверенного резервного пакета, затем устанавливает полный комплект обычным обновлятором. Проверена имитация прерывания этапов подготовки, замены и завершения; реальное отключение питания не проверялось. После перехода полный пакет установленной версии сохраняется в `packages` для следующего отката. У уже перешедших через Upgrade ZIP 0.2.6 его может не быть: тогда нужен полный пакет 0.2.6 из одноимённого релиза.

В проверке 2026-09-25 обычная установленная 0.2.6 была обновлена до 0.2.7 из опубликованного полного пакета: хост и endpoint сохранились, новый пакет остался в `packages` для следующего отката. Переход именно 0.2.5→0.2.7 и откат 0.2.7 на этом ПК не выполнялись.

**Окно обновления.** По «Перезапустить» окно программы рассыпается в пиксели и сжимается в окно обновления той же программы (версии «было → стало» и бегущая шкала); Velopack при этом работает с `--silent`, без своего диалога. Окно показывает процесс-наблюдатель (`Recovery.exe --watch-update … --update-window x,y`): оно встаёт ровно на место карточки старого окна, и только после этого старый UI завершается. Когда новая версия установлена, наблюдатель показывает «Готово», новая версия открывается на том же месте в виде той же карточки и вырастает в полное окно через пиксели. Её окно открывается полностью прозрачным (`LWA_ALPHA` 0) и становится видимым только после того, как дважды нарисовало карточку (счётчик кадров `tacho::frames`, запасной выход через 1,5 с); лишь затем наблюдатель получает `ui-shown` и закрывается. Пока окно слоистое, анимации открытия и закрытия окон Windows для него выключены (`DWMWA_TRANSITIONS_FORCEDISABLED`): в них ключевой цвет не действует. Передача идёт через файлы `.update/window-ready`, `.update/handoff`, `.update/ui-shown`; на время анимации окно становится слоистым с ключевым цветом (`WS_EX_LAYERED` + `LWA_COLORKEY`, цвет `#000000`), потому что окна tiny-skia не бывают полупрозрачными. Ключ именно чёрный: ещё не нарисованное окно (или кадр, потерянный, пока окно было полностью прозрачным) тоже чёрное, поэтому оно остаётся прозрачным, а не мелькает чёрным прямоугольником. Скругление карточки не рисуется на ключе: окно обрезается скруглённой областью (`SetWindowRgn`, `update_window::set_region`), а под углами лежит цвет рамки, иначе сглаженные края, смешанные с ключом, оставались тёмными точками вокруг углов. Так обрезаны окно наблюдателя, конец сжатия старого окна и начало новой версии до роста. Ключ снимается в кадре, который тут же выводится на экран (`update_window::with_next_frame`): поверхность остаётся слоистой, но полностью непрозрачной (`LWA_ALPHA` 255 без цветового ключа). Снятие `WS_EX_LAYERED` сбрасывало её картинку и могло дать чёрный прямоугольник. Если окно программы скрыто в трей, окно обновления появляется по центру экрана. Работает начиная с обновления, которое запускает версия с этим кодом: наблюдатель — копия старой версии. Кнопка **Настройки → Диагностика → «Анимация обновления»** проигрывает весь цикл по-настоящему, но без установки: программа останавливается как перед обновлением, сжимается в окно обновления, окно-заменитель (`--ui-update-rehearsal x,y`, та же версия «было → стало») 3 секунды «устанавливает», показывает «Готово» и перезапускает программу, которая вырастает из окна. `MicNoize.exe --ui-update-preview [x,y]` показывает одно окно обновления с имитацией установки во временной папке (для проверки вида).

**Карточка «Обновление готово»** в левой колонке показывает новую версию крупными цифрами и кнопку «Перезапустить». Пока обновление скачано и ждёт перезапуска, значок в трее и на панели задач несёт зелёную плашку NEW (рисуется в Rust поверх `app-64.png`; трей получает её через `mnr_tray_icon`). Когда обновление только что скачалось, она один раз празднует (≈3,3 с), как только окно на виду: сверху падает скошенная бирка «НОВОЕ», подпрыгивает, качается и раскрывается в карточку, которая плавно проявляется пиксельной волной с десятью общими контурами прозрачности; номер версии перекатывается со старого на новый и вспыхивает зелёным, вокруг кнопки расходится кольцо, из кнопки вылетает салют из скошенных сегментов на всё окно (выстреливает, тормозит о воздух и порхает вниз, покачиваясь и переворачиваясь; каждый цвет — один контур, поэтому кадр перерисовывает одно облако, а не десятки мелких областей), по кнопке проходит блик. Бирка и салют рисуются отдельным слоем поверх всего окна (`tacho::celebrate`), мозаика, кольцо и блик слоем карточки (`tacho::ready_fx`), перекат цифр `tacho::roll`. Слои праздника, ветра перезапуска и метаморфозы есть в окне только, пока играют: tiny-skia для каждой перерисовываемой области заново строит маску размером с окно под каждый слой, даже пустой. По клику «Перезапустить» кнопка вдавливается и выпадает из карточки одним из четырёх способов, выбранным случайно (тонет, проворачиваясь; выбивается и падает за край окна; откидывается внутрь, как люк; трескается на скошенные сегменты), на её месте остаётся тёмная щель с раскалённым на миг краем, и в неё со всего окна задувает ветер: 72 штриха и 24 частицы с независимыми задержками и паузами, без общих залпов; 12 фрагментов снимка интерфейса отрываются по очереди, поворачиваются и ускоряются к щели (`tacho::restart_slot` в карточке, `tacho::restart_wind` слоем поверх окна). Над щелью написан шаг подготовки («Проверяем версию…», «Сохраняем откат…», «Останавливаем звук…»), на её дне светится прогресс. Оставшаяся часть окна неподвижна; затем оно сжимается в окно обновления, продолжая картинку с уже оторванными частями. Ветер заканчивается при начале сжатия. Перезапуск ждёт не меньше 3,5 с после клика, чтобы кнопка выпала и фрагменты достигли щели; если перезапуск не состоялся (релиз отозван, подготовка не удалась), кнопка возвращается. Штрихи заливаются несколькими контурами (цвет × ступень яркости), поэтому кадр перерисовывает окно одним куском (≈9 мс): tiny-skia платит за каждую отдельную область, и контур на каждый штрих стоил 70 мс на кадр. **Настройки → Диагностика → «Карточка обновления»** показывает карточку с праздником на 8 с (с версией на патч выше); «Перезапустить» в ней проигрывает выпадение кнопки и ветер (≈3,8 с) и закрывает показ, ничего не перезапуская.

Публичные версии **Mic Noize** выходят в репозитории `Arkanoidvfx/MicNoize` как `Setup.exe`. Установщик и фоновые обновления сделаны через Velopack: программа проверяет обновления при запуске и каждые 15 минут, пока работает, в том числе в трее. Новая версия скачивается в фоне, после чего под вкладками на любой странице появляется панель «Доступно обновление» с кнопкой «Обновить и перезапустить» (в настройках блок «Обновления» только показывает состояние и проверяет вручную; версия программы стоит в заголовке окна рядом с названием: мелкие цифры 9 px, прозрачность 75 %). Программа закрывается, обновление применяется и она запускается снова. Перед этим кнопка ещё раз проверяет GitHub и, если за время работы в трее вышла версия новее скачанной, докачивает и ставит сразу её (без сети ставится уже скачанная), применение допускается после проверки комплекта UI/хоста и доступности полного пакета для отката. Начиная с 0.4.11 обновление применяется только с подписью Ed25519 ключа релиза (того же, что подписывает компоненты): рядом с полным пакетом в релизе лежит `<пакет>.sig.json`, подпись покрывает SHA-256 каждого устанавливаемого файла `lib/`, включая лаунчер и `Update.exe` от Velopack. Программа скачивает подпись сразу после пакета, хранит проверенную копию в `Components\.update` для применения без сети и перед применением проверяет её ещё раз; изменённый, лишний или отсутствующий файл, чужая версия или неверная подпись — обновление не применяется. Платная Authenticode-подпись пока не используется, поэтому Windows SmartScreen может показать предупреждение издателя.

Ожидание установки драйвера и появления виртуального микрофона в Windows показывается состоянием устройства; штатное ожидание TAG не создаёт красную ошибку. Отказы доступа и прочие реальные ошибки остаются видимыми.

Основной NVIDIA/TAG runtime устанавливается отдельно при первом запуске. Пока что-то ставится, чего-то не хватает или запуск голоса упирается в выбор устройства, на Шумодаве видна карточка: четыре плитки (компоненты NVIDIA и виртуального микрофона, модели шумодава для этой видеокарты, виртуальный микрофон, обработка голоса). Без поддерживаемой NVIDIA плитка моделей пишет «не нужны: шумодав на процессоре». У идущего шага видны фаза (подключение, скачивание, проверка SHA-256, распаковка, установка файлов), мегабайты или процент, скорость и шкала, сверху примерное время до конца; если сервер молчит 15 с, карточка так и пишет. Ошибка остаётся на своей плитке с кнопкой «Повторить» и короткой причиной (нет связи, нет места на диске, файл повредился, нет доступа к папке), скачанные части не пропадают. Если не скачались только модели, голос работает на процессоре, а после удачного повтора обработка перезапускается с моделями. Заголовок карточки называет проблему и её решение («Нет виртуального микрофона», «Микрофон не выбран», «Микрофон не найден», «Выход не TAG» с кнопкой «Настройки» и т. д.). Когда всё установлено, карточка уходит со страницы и появляется снова, только если позже что-то пропадёт или сломается. Подписанный TAG-драйвер ставится кнопкой «Установить» на плитке микрофона (или в настройках): один запрос UAC, `wdmdrvmgr.exe` с тем же INF, что и `install-tag.ps1`, настройки безопасности Windows не меняются; отказ показывается рядом с кнопкой, повтор без перезапуска программы. Пока идёт установка runtime или драйвера, автозапуск обработки ждёт. RVC runtime загружается только при первом включении Voice Changer. Модели голоса пользователя (`.pth`, `.index`, `.onnx`, `params.json`) не входят в релизы и должны импортироваться отдельно. Манифесты компонентов подписаны Ed25519, каждый архив и его части проверяются по SHA-256; уже скачанная валидная часть повторно используется после ошибки. Архивы `.tar.zst` распаковываются так: zstd снимает сама программа, а системный `tar.exe` получает обычный tar, поэтому установка работает и на Windows 10 / Windows 11 до 23H2, чей `tar.exe` не знает zstd. Используется `System32\tar.exe`, независимо от PATH. При ошибке распаковки сообщение сохраняет код выхода, последние четыре непустые строки stderr и ошибку чтения архива. Настройки, install ID, runtime и модели хранятся в `%APPDATA%\Mic Noize`, отдельно от программы в `%LOCALAPPDATA%\MicNoize`, и должны переживать её удаление. При первом запуске 0.2.0 `settings.ini` копируется из прежней `%LOCALAPPDATA%\MicNoiseReducer` (legacy migration); старые Components не переносятся.

Отдельные компоненты упаковываются через `scripts\package-components.ps1`. Редкие runtime-релизы собираются локально из vendor-папок, подписываются `COMPONENT_SIGNING_KEY` и публикуются через `gh release create`; эти большие сторонние входы намеренно не лежат в Git. Запасной workflow `release.yml` на GitHub-hosted Windows скачивает только закреплённые заголовки NVIDIA/TAG, проверяет проект и выпускает приложение. Секрет приложения: `MNR_TELEMETRY_SECRET`; без него телеметрия и отправка отчётов в обычной локальной сборке выключены, официальный локальный runner получает секрет из GitHub Actions. Каждая отправка включает метку поддержки `WindowsUser@ComputerName`, которая видна оператору в колонке User. Кнопка «Отправить разработчику» на вкладке «Логи» шлёт состояние движка, наличие core и моделей, ошибки установки, GPU, версию Windows и системного tar. К отчёту прилагаются хвосты `results/app.log`, `nvafx.log`, `tag-host.log`, `tag-host.previous.log`, `tag-endpoint.log`, `sessions.log`, `tag-headphones.log` и stderr распаковки `.download-rvc/rvc-runtime.tar.log`, а также ошибки запуска и паники из `%APPDATA%\Mic Noize\Logs`. Ранние логи TAG до появления core дополнительно читаются из `results` рядом с папкой `current`. Отчёт перечисляет время изменения приложенных логов, пустые и недоступные файлы; читаются только последние 8 КиБ каждого файла, отправляются до 2000 единиц UTF-16. Всё поступает как события `error` в панель оператора Mic Noize — отдельный воркер `micnoize-telemetry` со своей базой D1 (конфиг `telemetry/worker/wrangler.micnoize.toml` в репозитории Moment Player, код воркера общий); записи помечены `app_id = mic_noize`. Голос, имена файлов пользователя и содержимое моделей не отправляются.

Версия 0.2.0 завершает внутренний rename в **Mic Noize**: пакет/EXE, репозиторий, Win32-объекты и TAG-линии получили новые имена. Цепочка обновления 0.1.x намеренно не продолжается. `MNR` означает **Mic Noize Runtime**; ABI `mnr_*`, переменные `MNR_*`, `/mnr/` и `mnr_vcclient_server.exe` остаются без изменений.

По просьбе выпустить патч агент сам запускает `scripts\run-local-release.ps1 -Version X.Y.Z` после подготовки версии, заметок и синхронизации веток — пользователю не нужно вводить команду или секрет. Скрипт временно регистрирует локальный GitHub runner для одного задания: проверки и сборка идут в прогретом проекте, секрет поступает из GitHub Actions, загруженные файлы сверяются по SHA-256 до публикации. Повтор на том же коммите использует проверенный пакет и совпадающий черновик; после задания runner удаляется. 0.2.10 опубликована за 2 мин 58 с ([успешный прогон](https://github.com/Arkanoidvfx/MicNoize/actions/runs/36144041793)) против 12 мин 50 с у предыдущей GitHub-hosted сборки. Требуются чистый коммит и совпадение исходников с публичной веткой; полный порядок — в [release checklist](.agents/skills/micnoize/references/workflow.md#release-checklist). Подпись обновления (`scripts\sign-update.ps1`) берёт ключ релиза из `COMPONENT_SIGNING_KEY` (PEM): локальный runner получает его из одноимённого секрета GitHub Actions, которым подписаны и runtime-компоненты; при ручной упаковке подходит и файл по пути `COMPONENT_SIGNING_KEY_FILE`. Без ключа упаковка останавливается до публикации, а перед публикацией тот же код проверки, что у клиента, проверяет подписанный пакет встроенным в программу ключом. Запасной `release.yml` ключ не получает и приложение не выпустит.

## Сборка и запуск

Локальные dev-сборки запускайте из `bin`, не копируйте поверх `%LOCALAPPDATA%\MicNoize\current`: обновлятор сверяет установленный EXE с официальным пакетом текущей версии для безопасного отката. Редактирование хеша в `micnoize-bundle.json` эту проверку не заменяет. Установленную программу обновляйте штатной кнопкой.

Требуются Visual Studio 2022 C++ Build Tools, Windows SDK, CMake и Rust **1.97+ x86_64-pc-windows-msvc**. Проверено на Rust 1.97.1, MSVC 19.44 / SDK 10.0.26100.0. Отдельные CUDA Toolkit, TensorRT, Python и Node.js для запуска не нужны. Официальные NVIDIA, TAG и VCClient 2.1.4-alpha уже находятся в `vendor` (не в Git); права и условия их использования остаются отдельными.

```powershell
Set-Location D:\Projects\Audio\MicNoiseReducer
.\build.ps1
.\verify.ps1
.\enable-tag-host.ps1
.\run.ps1
```

`build.ps1` скачивает закреплённый Rubber Band 4.0.0 с проверкой SHA-256, собирает C++ и Rust по Cargo.lock. Кеш Cargo — `.cache/cargo`, результаты — `build`, exe — `bin`. `-NativeOnly` собирает только C++; `-Samples` — официальные примеры NVIDIA. Полный `build.ps1` пересобирает и `mic_tag_host`, и копирует UI поверх установленного — при работающих процессах он упадёт; для инкрементальной сборки см. [workflow.md](.agents/skills/micnoize/references/workflow.md).

`verify.ps1` пересобирает `mic_engine` и проверочные exe (`mic_check`, `effects_check`, `bridge_check`; хост и UI не трогает), затем запускает CTest, Rust-тесты и строгий Clippy. NVIDIA для этого не нужен.

Готовая dev-сборка: `bin\MicNoize.exe` (`Run.bat` = `run.ps1` с проверкой VRAM; запускать из Проводника, не из терминала агента). Она читает и сохраняет `%APPDATA%\Mic Noize\settings.ini`, но при наличии `vendor\nvidia-afx-3.0.0` всегда использует runtime и модели из репозитория; установленная версия использует `%APPDATA%\Mic Noize\Components`. При открытии программа сама выбирает сохранённые устройства и запускает обработку; без сохранённого выбора берётся HyperX, иначе микрофон связи по умолчанию Windows; допустимый виртуальный выход — TAG или Voicemeeter. В Discord поставьте устройство ввода **«По умолчанию»** (в игре — тоже «по умолчанию» или **Mic Noize (Thin Audio Gateway)**). Пока работает обработка через TAG, Mic Noize каждые полсекунды держит свой микрофон устройством ввода Windows по умолчанию для всех ролей (обычное и связи) через тот же системный интерфейс, что и панель «Звук». Зачем: при отходящем проводе физический микрофон заново появляется в Windows, и Discord сам переключается на него, если в нём выбрано конкретное устройство; на «По умолчанию» он остаётся на Mic Noize. Побочный эффект: все программы с микрофоном «по умолчанию» получают Mic Noize; выбрать другой микрофон по умолчанию, пока идёт обработка, нельзя — программа вернёт свой. Если Windows отклонит смену, обработка не прерывается, удержание отключается до следующего запуска. Суффикс — имя подписанного TAG-драйвера; наша capture-линия называется `MicNoize Microphone`. Установка TAG на новом ПК запускается кнопкой в настройках программы; `.\install-tag.ps1` остаётся путём разработчика (дополнительно проверяет подписи через signtool из Windows SDK).

## Постоянный виртуальный микрофон

В настройках **«Восстановить устройство»** сначала предлагает подтверждение остановки обработки. Проверка и перезапуск используют существующую исправную линию; переустановка допускается только с отдельной галкой и запросом UAC. Перед ней показано предупреждение о возможном новом идентификаторе и повторном выборе в Discord. После ошибки или завершения проверки восстанавливается прежнее намерение обработки; выход во время ремонта отменяет возобновление. На новом ПК установку драйвера нужно запустить кнопкой в настройках.

Хост доставляется рядом с UI в пакете приложения, отдельно от NVIDIA-моделей. `micnoize-bundle.json` содержит версии и SHA-256 обоих EXE. Перед остановкой звука обновление в фоне проверяет новый и предыдущий полные пакеты; при отсутствии совместимого пакета для отката применение прекращается. Старые пакеты без этого описания автоматически не мигрируют. Журнал `.update` в runtime сохраняет этап, копии пакетов, установщик и намерение обработки. На время замены задача приостанавливается; отдельный процесс и запись восстановления при входе в Windows продолжают незавершённую операцию. Проверка нового комплекта запускается до обычного UI; неудачная проверка вызывает установку сохранённого пакета. На отдельной Velopack-установке с настоящими UI/хостом проверены обновление, откат несовместимого хоста и восстановление смешанного/неполного комплекта. Готовность хоста проверяется и после отката; временные ошибки допускают ожидание 2/5/15/30/60 секунд. Помощники запускаются с рабочей папкой вне заменяемого `current`. **Это не проверка отключения питания. На установленном комплекте пройдены реальная перезагрузка, запрет exclusive и измерение громкости в общем режиме; чистая установка, сон и переподключение физического микрофона остаются непроверенными.**

Политика общего режима TAG записывается через Windows PolicyConfig без повышения прав приложения, с обязательным чтением результата. UI и хост обновляются согласованно; переустановка драйвера для смены способа записи не требуется.

Постоянный хост удерживает уровень виртуального микрофона, в том числе при закрытом UI. **Mic Noize поддерживает только общий режим WASAPI:** хост запрещает монопольный доступ именно к подтверждённому endpoint, проверяет настройку при привязке и раз в секунду, восстанавливает её после изменения. Постоянный тестовый захват для этого не открывается. Программы с обязательным exclusive-режимом получат отказ; несколько обычных клиентов могут работать одновременно. Запрет проверяется чтением после записи; ошибка политики снимает готовность и оставляет тишину. Используемое свойство Windows не входит в публичный SDK, поэтому совместимость проверена только на текущей Windows; на другой версии нужен такой же функциональный тест. Физический микрофон и другие endpoints не регулируются. На TAG 2.0.0.1903 сохраняется компенсация -30 дБ для обычного захвата: драйвер усиливает его в 31,6228 раза и отклоняет `SetVolumeControlParams`. Требование одинаковой громкости в обоих режимах заменено согласованным запретом exclusive. Перезагрузка и остальные проверки полного плана ещё не завершены. Подробности — [проверка драйвера](driver-feasibility.md#проверка-диапазона-громкости-2026-09-24).

Для повторения проверки: собрать `mic_tag_probe` через CMake. `bin/mic_tag_probe.exe --endpoints` только читает состояние; `--host-status` читает готовность, живость процесса, выбранную линию, endpoint и компенсацию. `bin/mic_check.exe --tag-level-watch-check` проверяет возврат master/каналов на 100 % и снятие Mute работающим хостом, в том числе с закрытым UI. `--lines` и `--volume-range LINE_ID` требуют остановленного хоста; `--signal-shared ENDPOINT_ID` и `--signal-exclusive ENDPOINT_ID` — работающего хоста при остановленной обработке. Они передают в виртуальный микрофон синтетический тон, который могут получить другие открытые приложения; речь и аудиофайлы не записываются. Проверка диапазона восстанавливает прежние параметры, если драйвер принял изменение; код возврата 2 означает блокер диапазона, 1 — ошибку проверки. Команды сами не завершают процессы, не создают линии и не переустанавливают драйвер.

`mic_tag_host.exe` постоянно владеет TAG; UI и шумодав передают ему готовые отсчёты через подтверждаемый блок разделяемой памяти. Второй очереди воспроизведения нет. При выключенном движке хост выдаёт точную тишину, не открывает физический микрофон и не загружает NVIDIA. Если производитель звука прекращает передачу дольше чем на 50 мс, хост переходит на тишину; когда производитель возвращается, он заново регистрируется и продолжает в той же сессии (одна короткая пауза, счётчик `reconnects` в `sessions.log`). Готовность endpoint не требует слушателя; без принимающего клиента аудиотаймер хоста отключён. Если обработка остановилась с ошибкой, UI повторяет запуск через 2, 5, 15, 30 и 60 с. Для распознанных временных ошибок endpoint/Windows Audio/связи с хостом ожидание продолжается раз в 60 с; остальные ошибки ограничены пятью попытками. Минута нормальной работы обнуляет счётчик. «Обновить устройства» сбрасывает прежнюю ошибку и задержку попыток. [Официальное описание TAG](https://software.muzychenko.net/en/thin-audio-gateway/).

Отдельный поток хоста удерживает master и каналы **своего** виртуального микрофона на 100 % и снимает его системный Mute: по уведомлениям Windows и контрольной проверке раз в секунду, с чтением результата после записи. Собственные изменения помечаются GUID. Это работает после Stop и полного выхода из UI, пока жив хост. Физический микрофон не регулируется; собственный Mute Mic Noize остаётся финальным в аудиотракте. Перед TAG движок компенсирует максимальное усиление endpoint (на проверенном ПК +30 дБ), сохраняя уровень **обычного общего захвата Windows**. Монопольный захват запрещён на этом endpoint; несколько программ используют обычный общий режим Windows. При потере подтверждённого endpoint/контроля уровня хост передаёт тишину. Журнал контроллера `results/tag-endpoint.log` ограничен 256 КиБ с одним предыдущим файлом.

Хост находит Windows endpoint по экземпляру драйвера и KS-топологии выбранной capture-линии. Отображаемое имя и порядок перечисления не используются; неоднозначное совпадение даёт ошибку. Движок и монитор получают один endpoint из согласованного снимка `TagEndpoint.v2`: PID/время запуска, GUID хоста, версия, готовность и компенсация. Проверка живости не открывает тестовый захват и не блокирует аудиоканал. Новые `TagLink.v2` и `HeadphoneLink.v2` проверяют идентификаторы хоста/соединения, номера и сроки запросов, размеры и конечность сэмплов. Старые `.v1` не переопределяются. После тайм-аута соединение больше не отправляет команды, включая запоздалый Stop. UI и хост нужно заменять согласованно; совместимость файла хоста проверяется по встроенной версии, без запуска EXE.

В настройках отображается состояние устройства: запуск, ожидание драйвера, ожидание endpoint Windows, готовность, временное восстановление или необходимое действие. Проверка выполняется рабочим потоком и не требует подключённого слушателя.

«Обновить устройства» проверяет хост и перечитывает список даже при работающем микрофоне. Исправный маршрут остаётся активным; незавершённый запуск отменяется, устаревшие ответы игнорируются. После успешного запуска прежняя ошибка очищается. Возврат устройства и пробуждение вызывают проверку списка; сохранённый физический микрофон не подменяется другим.

Переключатель **«Запускать Mic Noize вместе с Windows (в трее)»** включён по умолчанию (`[ui] app_autostart`) и управляет обоими стартами при входе. HKCU Run `MicNoize` = `"<exe>" --start-tray` запускает окно в трей; значение переписывается при каждом запуске, чтобы следовать за текущим exe. Триггер входа задачи хоста в Планировщике Windows поднимает виртуальный микрофон сам, не дожидаясь окна, поэтому Discord или игра, стартующие вместе с Windows, находят устройство. Выключение убирает и то и другое. Отдельного переключателя для микрофона нет; прежний `[ui] tag_autostart` не читается, и при первом запуске UI выставляет триггер по этому переключателю. Администратор не нужен. Задача работает в интерактивном сеансе, без лимита времени, зависимости от простоя/сети и остановки на батарее. Параллельный экземпляр запрещён. Прежняя запись Run удаляется только после проверки задачи; выбор автозапуска сохраняется. `enable-tag-host.ps1` включает вход и запускает хост сейчас, `-Disable` отключает только вход, `-Remove` удаляет задачу и старые записи Run; при следующем запуске UI снова выставляет вход по переключателю «Запускать Mic Noize вместе с Windows». Уже работающий хост при удалении задачи остаётся до штатной остановки/выхода из Windows. При недоступности Планировщика UI запускает хост напрямую и сообщает об отсутствии восстановления с закрытым UI.

Задача держит процесс наблюдения и его аудиопроцесс. После падения или отсутствия heartbeat 15 секунд аудиопроцесс перезапускается через минуту. При падении наблюдателя работающий аудиопроцесс сохраняет endpoint и через 60 секунд бодрствования возвращает наблюдателя через Планировщик; тот проверяет путь EXE, PID/время создания и сеанс. Отдельная короткая задача проверяет состояние раз в минуту и восстанавливает пару даже при потере обоих процессов; обнаружение сбоя плюс минутная задержка занимает до двух минут. Зависание самого наблюдателя обнаруживает отдельная задача по его heartbeat; она завершает только процесс с подтверждёнными путём, временем создания, поколением и сеансом, сохраняя исправный аудиопроцесс. Из-за минутного опроса это может занять около трёх минут; при зависании обоих процессов затем требуется перезапуск аудиопроцесса. Общий лимит трёх повторов сохраняется в реестре вместе с поколением операции и идентификатором входа в Windows: гибель обоих процессов его не обнуляет. Stop отменяет поколение и отключает задачу восстановления; запоздалые команды не включают отменённый хост. Задача восстановления имеет `Volatile=true`: Windows отключает её при загрузке, а разрешённый запуск хоста снова включает. Автозапуск пользователя не меняется. Исчерпание попыток отражается в UI; «Обновить устройства» возобновляет безопасное восстановление. Отсутствие слушателей не считается зависанием; время сна исключается из watchdog. **Выход** из UI останавливает обработку физического микрофона, оставляя хост с тишиной. На проверенной Windows встроенный `RestartOnFailure` не повторяет запуск после ошибки процесса, поэтому он не является единственным механизмом восстановления.

Start/Stop не удаляет и не пересоздаёт виртуальную линию. Это не системная служба до входа в Windows: выход из Windows или сбой драйвера отключает endpoint. Запуск игр до готовности хоста также не гарантирует доступность устройства. После потери endpoint внешней программе может потребоваться повторное открытие аудиопотока. Тот же хост обслуживает наушники (`HeadphoneLink.v2`, отдельно от `TagLink.v2`); глобальная блокировка защищает владельца драйвера от второго сеанса. Чужие процессы не завершаются.

Хост повторно использует свою capture-линию `MicNoize Microphone`, а новую создаёт с `EpName="Mic Noize"`. ID микрофона и наушников сохраняются в DWORD `MicrophoneLineId`/`HeadphoneLineId` под `HKCU\Software\MicNoize\TAG\4d699d4a-65a5-40ec-9875-8e6d5fc01e0c`. Первое выделение начинается с 3: подписанный demo-драйвер после загрузки восстанавливает свои линии 1/2. Если сохранённый ID занят другой линией или собственных линий несколько, хост сообщает конфликт вместо выбора нового ID. Чужие и старые отключённые endpoints автоматически не удаляются. Реальная перезагрузка 2026-09-24 подтвердила автозапуск, имя **«Mic Noize (Thin Audio Gateway)»**, 100% и запрет exclusive, но обнаружила смену прежней линии 1 на 3. В build 2026092406 добавлено сохранение ID; повторный запуск хоста сохранил текущий endpoint. Повторная загрузка Windows 2026-09-24 в 21:22 подтвердила сохранение того же endpoint/линии 3, автозапуск, имя, 100%, снятый Mute и запрет exclusive; два shared-клиента получили кадры без Refresh или перезапуска хоста. Чистая установка ещё требует проверки. Mic Noize не меняет выбор устройства в Discord; после уже произошедшей смены endpoint может потребоваться повторный выбор пользователем.

Подписанный demo-драйвер поддерживает три линии. В «Восстановить устройство» отдельная галка разрешает удалить только стандартную capture-линию TAG (ID 1, проверенная KS-идентичность), чтобы освободить место для наушников, и перенести собственные старые линии 1/2. Согласие сохраняется: после загрузки хост удаляет эту же восстановленную драйвером стандартную линию. Исправные собственные линии сохраняются; повторный ремонт не создаёт дубликатов. Возможная смена старого endpoint объясняется перед подтверждением. Защита мониторинга и выхода наушников от петли распознаёт TAG по драйверу и KS-топологии, поэтому переименование не обходит её.

Штатный запрос периода — 5 мс; реальный QuadCast S использует 10 мс. Буфер 40 мс — запас от обрывов, не полная задержка. Речевой замер через TAG дал около 120 мс без Discord (см. CHANGELOG).

## Интерфейс

Кнопка **«Как пользоваться»** рядом с заголовком **«Шумодав»** открывает внутри окна картинку с выбором Mic Noize в Discord. Картинка встроена в exe; отдельный `guide.png` пользователю не нужен. «Назад» или Esc возвращает на «Шумодав», не меняя обработку звука.

Появление карточки готового обновления начинается только в открытом окне с фокусом, после завершения сборки интерфейса. При потере фокуса, сворачивании или уходе в трей вся последовательность — бирка, проявление кнопки, смена версии, блик и конфетти — замирает и продолжает с того же момента при возвращении. Финальное распикселивание окна проявляет чёткий интерфейс под исчезающими блоками; волна и прогрев ползунков ждут его завершения. Области бирки, карточки и смены версии объединены, чтобы не перерисовывать перекрывающиеся части окна много раз за кадр.

Слева — меню разделов: **Шумодав**, **Эффекты**, **Саундпад**, **Смена голоса**, внизу **Настройки** (там же кнопка «Логи и отчёт») и, при готовом обновлении, карточка «Обновление готово» с кнопкой перезапуска. Tab идёт по видимому порядку страницы, затем по меню; Tab / Shift+Tab перемещают видимый фокус, Enter / Space активируют, стрелки меняют значения (ползунок, тронутый мышью, тоже получает фокус для стрелок, но его рамка видна только после клавиатуры, как `:focus-visible`); Esc закрывает панель наушников или правку слова реверса, из логов возвращает в настройки, с остальных страниц — на «Шумодав». Смена раздела отмечена пикселизацией, которая ничего не задерживает: новая страница рисуется чёткой с первого кадра, как без эффекта, а поверх неё лежит её же мозаика и за 10 шагов по 12 мс растворяется волной слева направо: блоки мельчают с 16 до 5 px, каждый столбец плавно гаснет вслед за волной (с 90 % до нуля). Часы идут от первого кадра перехода: опоздавший кадр пропускает шаг, а не растягивает переход. Для мозаики в память в масштабе 1/4 рисуется только новая страница; анимация только в активном окне. В **Настройки → Визуальные эффекты** её можно выключить (`[ui] page_pixelate`): тогда раздел открывается сразу и страницы в память не рисуются. Кадры, где меняется почти вся страница (смена раздела, момент её проявления, поиск, сортировка и смена раздела саундпада), окно перерисовывает одним проходом, а не десятками отдельных областей; при сворачивании и потере фокуса (переход в игру) лишнего кадра нет. Справа в заголовке — подпись «by ARKANOID» в стиле бирок ползунков. Строка ошибки появляется над страницей только при проблеме; постоянного статуса «работает» нет. Окно 1040×740, минимум 960×680 логических пикселей; 620×440 — только QA-флаг `--ui-small`. Шрифты встроены в exe из `ui/assets/fonts` (SIL OFL 1.1, лицензии `OFL-*.txt` рядом). Игровой Russo One — цифры, время записей, заголовки страниц и логотип; у него нет знака U+2212, поэтому отрицательные значения пишутся дефисом. Интерфейс — Onest с ролями: заголовок страницы 24 (Russo One), лид под ним 13, заголовок карточки 14 SemiBold, шапка колонок 11 SemiBold приглушённым цветом, текст и подписи полей Regular, кнопки, выбранный пункт меню и выбранная вкладка Medium, поясняющие подсказки 12 приглушённым цветом; символ ∞ берётся из системного шрифта. Клавиши и логи — Consolas, значки — Segoe MDL2 Assets.

**Шумодав**: сверху то, что можно сменить, — микрофон и наушники (картинка и список), у наушников шестерёнка открывает поверх страницы панель «Что слышите вы». Обработка и выход (модель NVIDIA/CPU и виртуальный микрофон) не выбираются здесь и свёрнуты в строку «Обработка и выход». Ниже индикатор «До / После» (уровень входа и выхода, шкала от −72 дБ: шипение сырого микрофона видно на «До», а остаток после шумодава на «После» — тишина; «До» — рваные, спокойно мерцающие столбики, «После» — чистые скошенные сегменты с зелёным градиентом и светящимся краем, без метки пика), «Шумоподавление» и «При удержании клавиши» с хоткеем, под ними панель «Подбор под микрофон». **Эффекты**: эффекты разложены на две группы, переключатель справа от заголовка: «Голос вживую» (усиление, Formant Shift, эхо, AutoTune: звучат, пока держите клавишу) и «Фразы и повторы» (замедление, ускорение, реверс, застревание: записывают кусок и проигрывают). Видна одна группа, поэтому блок «Слышать себя», громкость Discord и повтор последнего остаются на экране без прокрутки; выбор сохраняется в `[ui] effects_group`. Если сработал эффект скрытой группы, её вкладка подсвечивается оранжевым. Tab: сначала переключатель, затем строки видимой группы. восемь строк с иконкой, ползунком и клавишами для своего голоса и для Discord; Formant Shift, Echo, Застревание и AutoTune раскрывают дополнительные настройки. Сработавший эффект подсвечивает строку. В строке реверса — слово для тренировки: оно разворачивается задом наперёд, при наведении замирает в перевёрнутом виде, по клику вписывается своё (до 12 символов); Enter, Esc или клик мимо поля завершают ввод. Внизу — прослушивание, громкость Discord и повтор последнего с шестью записями.

Оранжевый — то, что включено или происходит сейчас, и главное действие страницы; выбранный раздел меню нейтральный. Хоткеи показаны клавишами-кейкапами; пока окно в фокусе, нажатая назначенная клавиша с коротким «проседанием» опускается на 3 px, становится оранжевой и светится (читаются только назначенные клавиши). Пустой слот — «+ клавиша». Переключатели заменили галочки.

Ползунки «Тахометр»: скошенные сегменты, значение на бирке над краем (или справа в компактном виде). Красная зона: «Шумоподавление» и «При удержании клавиши» строго выше 100 % (под «Шумоподавлением» появляется предупреждение, а позади — две перекрещённые ленты «экспериментально», проходящие над шкалой), громкость усиления выше 1600 % (пока включена «перегрузка», вся шкала усиления раскаляется от оранжевого к красному, деления дрожат рваными верхушками, сверху красная линия «потолка», число красное). Знаковые (высота, тон RVC) заполняются от центра. «Замедление» зеркально: ×0,50 справа. Эти значения эффектов (усиление 167 %, высота −6, ×0,67 / ×1,67) один раз выставляются и у прежних установок, в которых нет `[effects] defaults_version=2`; дальше выбор пользователя сохраняется. Ctrl+клик возвращает исходное значение (шумоподавление 40 %, при удержании 10 %, усиление 167 %, высота −6, ×0,67 / ×1,67, Discord 100 % и т. д.). Шаг у всех ползунков один: 1 % (усиление, громкости, усиление RVC), 0,01× (замедление и ускорение), 1 полутон; так же двигают стрелки клавиатуры. Щелчок по шкале ставит значение под курсором; захват рядом с текущим краем сохраняет значение без скачка. Обычное перетаскивание проходит весь диапазон за длину шкалы, в том числе усиление и задержку эха. **Shift + перетаскивание** — точная доводка: движение в пять раз медленнее, на плотных шкалах не менее 2 логических px на шаг. Shift можно нажимать и отпускать во время движения; нажатие с Shift сохраняет текущее значение даже вдали от края. Дробные движения курсора накапливаются, у границ шкалы обратное движение отвечает сразу. Цифры и заполнение показывают выбранное значение сразу; отпускание мыши вне шкалы завершает доводку, потеря фокуса отменяет захват. Колесо мыши над ползунком двигает его на шаг за щелчок (тачпад: шаг за 24 px), страница под ним при этом не прокручивается; у громкостей строк саундпада колесо не работает, чтобы список прокручивался. Гейт на «После» поддерживает ту же механику захвата и Shift, колесо меняет порог на 1 дБ. Слово реверса во время перелёта рисуется контурами глифов (дробные позиции вместо целых пикселей) с кадрами каждые 7 мс. В заголовке окна название «MicNoize» слитно; наведение на «by ARKANOID» зажигает подпись (пульсирующее оранжевое свечение) и, пока указатель на ней, всё окно глитчует пикселями: полосы его же снимка съезжают в стороны с голубой и красной каймой, мелькают блоки и строки (новый рисунок каждые 70 мс, `tacho::glitch`). Анимации: волна сегментов в простое (раз в 8 с, ползунки одной страницы продолжают её друг за другом), прогрев шкал при показе окна (обе выключаются переключателем «Волна и прогрев ползунков» в **Настройки → Визуальные эффекты**, `[ui] slider_idle`), вспышка края, «призрак» прежнего края при уменьшении; наведение мыши ползунок не подсвечивает. Кадры запрашиваются только пока идёт анимация; в неактивном, свёрнутом или скрытом окне анимации нет.

При перетаскивании светящийся край и бирка плавно следуют за курсором по всей шкале, включая движение внутри одного шага высоты тона. Числа и звук сохраняют заданный шаг; Shift по-прежнему даёт точную доводку. Частые события мыши объединяются до последнего значения за ближайший кадр, который запрашивается сразу, без ожидания таймера анимации. При регулировке, в том числе внутри одного шага, окно рисуется одним проходом: живые индикаторы и движущийся край не дробят отрисовку на десятки перекрывающихся областей. После регулировки возвращается обычная перерисовка изменённых областей. Отпускание мыши и потеря фокуса сохраняют последнюю позицию. Та же обработка ввода работает на гейте «После». Сон служебных таймеров, загрузки и файловые операции выполняются в отдельных потоках и не останавливают поток окна, поэтому движение мыши обрабатывается сразу, а не между тиками таймера.

Фоновый UI: при потере фокуса, сворачивании или скрытии в трей опрос индикатора и его затухание отключены; служебный цикл — раз в 250 мс вместо 50 мс. Аудио, native-опрос хоткеев и heartbeat продолжают работать независимо.

**Крестик** сворачивает окно в трей, обработка продолжается. Клик по значку программы в панели задач, когда окно активно, тоже убирает его в трей (как в OBS); если событие сворачивания или потери фокуса пропущено, окно скрывается после ближайшей проверки состояния (обычно до 250 мс). Кнопка «−» сворачивает в панель задач как обычно; после восстановления окна следующий клик по значку снова убирает его в трей. Любое другое системное сворачивание (например, Win+M) тоже уводит окно в трей. Меню значка: **Открыть Mic Noize**, **Перезапустить**, **Выход**. Перезапуск сохраняет настройки и останавливает UI/движок перед запуском нового процесса, не завершая `mic_tag_host`. Повторный запуск показывает существующее окно. Оранжевый микрофон встроен в EXE; при ошибке создания значка трея окно остаётся открытым.

Выход микрофона, модель (Denoiser v1 / v2) и буфер (10–80 мс) меняются при остановленной обработке в настройках. Отсутствующее сохранённое устройство не заменяется другим автоматически: подключите его, нажмите «Обновить устройства» — обработка запустится снова. Ошибка тракта останавливает обработку и показывается вверху окна; повторный запуск — тем же «Обновить устройства» или сменой микрофона.

## Шумоподавление

- **Шумовой гейт на «После»** — кликните или перетащите оранжевый порог прямо по полоске. Диапазон −71…0 dBFS, шаг 1 dB; край слева (−72), правая кнопка мыши или Enter при фокусе выключают гейт. Tab переводит фокус на полоску, стрелки меняют порог. По умолчанию гейт выключен; `[audio] noise_gate_db` сохраняется. Ниже порога микрофон закрывается, с удержанием 120 мс, гистерезисом 3 dB и плавными переходами 10 мс без дополнительного буфера. Гейт управляет живым голосом после шумодава/RVC, включая фоновый голос при Discord/повторе и запись микрофона в студии. Все эффекты получают сигнал до гейта: тихие фрагменты, записи фраз, стуттер, эхо и повтор не обрезаются; воспроизводимые эффекты, Discord и soundpad обходят гейт. RVC без хоткей-эффектов остаётся голосом под гейтом. «После» показывает очищенный микрофон **до гейта**, чтобы видеть шум при закрытом гейте; подбор силы шумодава тоже использует этот уровень. Подсказка напоминает отключить гейт в Discord, чтобы голос не обрезался повторно.
- Основной уровень «Шумоподавление» 0–200 %, на новой установке 40 %; 101–200 % помечены как эксперимент (оранжевое предупреждение под ползунками появляется, только пока один из уровней выше 100 %) и напрямую передаются SDK без второго прохода. Официальный диапазон NVIDIA — 0–100 %; SDK может отклонить запрос или ограничить воздействие. При отказе возвращается явная ошибка с указанием вернуть 100 %. Увеличение силы подавления не подтверждено. 0 % не является обходом вызовов SDK.
- **«При удержании клавиши»** — второй уровень (на новой установке 10 %) с отдельным хоткеем (по умолчанию не назначен). Пока клавиша удерживается, DSP применяет второй уровень к NVIDIA, после отпускания — основной, без перезапуска модели. Значения сохраняются в `[audio] intensity` / `alternate_intensity`, хоткей — `[effects] noise_key`. Работает вне фокуса и в трее; Mute, остановка, потеря клиента, lock/sleep, переназначение и heartbeat старше 250 мс возвращают основной уровень и требуют свежего нажатия. Discord обходит NVIDIA, настройки наушников независимы.
- **«Подбор под микрофон»** — панель под ползунками. «Подобрать»: ~4 с тишины, за которые ползунок сам проходит силы 0, 10, … 70, 85, 100 % и на каждой меряет остаток шума после шумодава (медиана пиков «После»); выбирается самая мягкая сила от 10 %, при которой остаток не выше −70 дБ (под нижней границей индикатора), иначе 100 % (выше 100 % подбор не заходит). Затем ~3,5 с голоса: если на выбранной силе голос выходит тише входа больше чем на 6 дБ, сила снижается на шаг. Если во время тишины треть замеров громче −35 дБ, подбор просит повторить. Ход виден на графике: скошенный столбик на силу высотой с остаток шума, пунктир — граница тишины, зелёные — тихо, выбранный светлый. Результат сразу применяется и сохраняется для этого микрофона (`[noise_profiles] <id микрофона>=<процент>`); при смене микрофона его сила ставится сама. «Вернуть N %» откатывает силу и прежний профиль. Подбор идёт только при запущенной обработке, с NVIDIA или DeepFilterNet, в активном окне; движение ползунка руками, смена микрофона, остановка обработки или уход окна на задний план его прерывают (сила возвращается прежняя). «Послушать себя» включает прослушивание всего голоса, как «Весь голос» на странице «Эффекты».
- Входную громкость задаёт Windows у физического микрофона; основной уровень выхода фиксирован на 100 %.

## Эффекты и хоткеи

Восемнадцать назначений: девять эффектов × два источника («Микрофон» и «Discord»), плюс прослушивание, повтор последнего и второй уровень шумоподавления. Под каждым эффектом нажмите **Назначить**, отпустите исходные кнопки, нажмите клавишу/сочетание или Mouse 3/4/5 и подтвердите. Ctrl/Alt/Shift учитываются точно; одинаковые сочетания для двух назначений и саундпада запрещены. Esc отменяет, «Убрать хоткей» очищает. Клавиши продолжают поступать игре. Работа во всех играх/защищённых окнах не гарантируется; программа не повышает права.

| Эффект | Диапазон | Поведение |
|---|---|---|
| **Усиление** | 100–2000 % (×1…×20), исходно 300 % | Действует на выходе строго при удержании, переход 10 мс. Мягкое насыщение после усиления; при 100 % и без удержания насыщение обходится. Для усиления конца фразы держите кнопку немного дольше. |
| **Перегрузка** (галка) | — | По умолчанию выключена. Жёсткий клиппинг с входным усилением ×12, пик ±0,891. Работает только при удержании усиления выше 100 %, для обоих источников и выходов; без галки — мягкое насыщение. Переключение сглажено за 10 мс. Чтобы в эффект попадали дыхание и клавиатура, снизьте шумоподавление: удалённое NVIDIA не восстанавливается. |
| **Размер голоса** | Форманты −12…+12 (исходно −5, «крупнее 5»), тон в «тон» −12…+12 (исходно 0) | Главный ползунок двигает только форманты: тот же голос звучит крупнее (влево) или мельче (вправо) без смены высоты; тон настраивается отдельно. Один Rubber Band shifter без изменения темпа; без удержания — полный обход без задержки. |
| **Замедление / Ускорение** | ×0,50…×0,95 (исходно ×0,70) / ×1,05…×2,00 (исходно ×1,50), шаг ×0,05 | Удерживайте и говорите, затем отпустите: фраза прозвучит с выбранной скоростью и соответствующей высотой. Скорость фиксируется в начале записи. Максимум 10 с в памяти, без файлов. После отпускания захватывается ещё 200 мс окончания слога; при заполнении буфера ждём отпускания. Во время удержания микрофон проходит без заглушения; при воспроизведении звучит обработанная версия; вне фразы задержки нет. |
| **Реверс** | — | Пока удерживаете, обычная речь идёт в чат и записывается. После отпускания — ровно 150 мс тишины, затем только обратная версия с исходным уровнем и скоростью ×1, без дополнительного захвата 200 мс. Конец плавно затухает за 60 мс (для короткой фразы — не дольше половины длины), живой голос возвращается за 10 мс. Лимит 10 с. |
| **Echo** | Интервал повторов 60–2000 мс (500), повторы 1–8 (3), затухание 0–90 % (55), уровень 0–100 % (100) | Пока хоткей удерживается, слышны только повторы исходного голоса, без сухого сигнала и самоповтора. Основной ползунок «Интервал повторов» задаёт расстояние между повторами; изменения применяются со следующего нажатия. После отпускания обычный голос возвращается сразу, хвост доигрывает до 16 с с плавным концом. |
| **Застревание** | Фрагмент 50–300 мс (120) | При нажатии захватывает последние отсчёты выбранного источника и повторяет их до отпускания со сглаженными стыками. |
| **AutoTune** | Подтяжка 0–150 мс (0 = «робот»), тоника C (0), хроматика / мажор / минор / минорная пентатоника (пентатоника), сила 0–100 % (100) | При 0 мс голосовой тон 80–800 Гц мгновенно встаёт на ближайшую ноту гаммы, ступеньками, как у T-Pain; коррекция до ±4 полутонов. Нота сменяется, только когда другая ближе на четверть тона, поэтому не дрожит между двумя. Окно анализа с тихой четвертью (начало или конец звука) пропускается. Через согласные и паузы нота держится 120 мс, затем коррекция плавно уходит к нулю. Пока держите хоткей, обработка и её задержка сохраняются на согласных и паузах. |

Бережная подрезка реверса: микрофон и Discord автоматически убирают только непрерывные практически беззвучные края от 200 мс, оставляя по 100 мс рядом со звуком; внутренние паузы сохраняются. Анализ по пикам окон 10 мс с порогом `min(0.0001, пик записи × 0.001)`; равенство порогу сохраняет окно. Записи короче 300 мс и с пиком ≤ 0.001 остаются целиком. Шумные края могут не обрезаться. Это пороговая обработка, не распознавание речи.

Обработка выбранного источника: Застревание → тон, форманты и AutoTune → фразы и усиление → Echo. Неактивные эффекты обходятся без постоянной задержки. Правила для фраз: сохраняется сигнал после шумоподавления и RVC; громкость и Mute действуют на текущее воспроизведение. Отмена, Mute, Stop, потеря клиента, блокировка/сон, переназначение и устаревший опрос клавиш (250 мс) сбрасывают фразу и эффекты, включая Echo-хвост — отпустите и снова нажмите хоткей. Новый хоткей во время проигрывания начинает новую запись. Одновременное нажатие нескольких хоткеев фразы отменяет запись/воспроизведение; сначала отпустите все эти клавиши. Живые эффекты можно удерживать одновременно. Granular удалён: старые хоткеи для него отключаются, остальные назначения сохраняются. Сохранённый интервал Echo сохраняется; 500 мс — начальное значение для новых настроек.

**Повтор последнего** — Ctrl+F8 по умолчанию, сочетание меняется кнопкой рядом. Один общий слот для всех эффектов, кроме усиления, только в памяти, до 20 с обработанного звука (покрывает 10 с записи при ×0,5). Новое удержание заменяет фрагмент; для скорости/реверса сохраняется обработанное воспроизведение, для Echo — только повторы до конца хвоста, без вернувшегося сухого голоса. Нажатие после окончания эффекта проигрывает фрагмент поверх живого микрофона; повторное — с начала. Во время записи нового эффекта повтор игнорируется. Микрофон не сохраняется в Discord-фрагмент. Mute, отмена и сбросы останавливают повтор; остановка движка очищает слот. **Усиление не записывается**: его удержание не заменяет фрагмент и не попадает ни в повтор, ни в запись. Discord-громкость применяется при каждом воспроизведении.

**Последние записи** — блок «Повтор последнего» на странице «Эффекты». Каждый законченный фрагмент сохраняется в `%APPDATA%\Mic Noize\Записи` файлом `Запись ГГГГ-ММ-ДД ЧЧ-ММ-СС (mix).wav` (48 кГц моно, 16 бит); хранятся шесть последних, более старые удаляются при следующей записи. В WAV Discord-эффекта уже применена громкость на момент завершения записи; микрофонный эффект сохраняется без ослабления. Плитка воспроизводит этот уровень без громкости и выравнивания саундпада, поэтому последующее движение ползунка Discord старый фрагмент не меняет. Старые WAV без `(mix)` не содержат сведений об источнике и уровне: при воспроизведении к ним применяется прежний коэффициент Discord 100 % (0,08), что приблизительно восстанавливает Discord-записи с настройкой 100 %. Все шесть записей — одинаковые компактные плитки по три в ряд, новейшая первой, без прокрутки: время записи, клик или Enter запускает её как звук саундпада (повторное нажатие останавливает, играющая подсвечена оранжевым, тонкая полоска под ней показывает прогресс; при реверсе заполняется справа налево). У каждой записи рядом с воспроизведением есть кнопка реверса: она играет ту же запись задом наперёд (развёрнутая копия загружается вместе с обычной), волна карточки при этом заполняется справа налево. Кнопка сохранения есть на каждой записи и открывает выбор прямо под строкой этой записи: **В саундпад** (если папка ещё не выбрана — сначала предложит её выбрать и сразу подключит) или **В папку…**. Там же показывается результат сохранения или ошибка. Копия не перезаписывает одноимённый файл: к имени добавляется ` (2)`. Дата остаётся в имени файла. Список переживает перезапуск программы. Обе галочки прослушивания стоят слева, под «Слышать весь голос».

### Discord

Захват включает только дерево процессов настольного Discord (Discord, PTB или Canary, одна запущенная версия; браузерный Discord не поддерживается) через официальный [Windows Application Loopback API](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/). Игра, музыка других приложений и наше прослушивание исключены. После назначения Discord-хоткея запустите обработку и дождитесь «Discord · готов»; при перезапуске Discord источник переподключается автоматически, для эффекта нужно новое нажатие.

Усиление, Размер голоса, Echo, Застревание и AutoTune работают во время удержания; скорости записывают фрагмент и проигрывают после отпускания; реверс записывает фрагмент без передачи исходной речи в виртуальный микрофон и через 150 мс проигрывает только обратную версию. Обычный звук Discord в ваших наушниках не выключается. Discord подмешивается к живому микрофону и обходит NVIDIA и RVC; ваш микрофон при этом продолжает проходить шумоподавление и RVC. Пока удерживается Discord Echo, обычная микрофонная подмешка подавляется, саундпад продолжает звучать отдельно; после отпускания голос возвращается вместе с Echo-хвостом. Источник фразы фиксируется до её окончания.

**Громкость эффектов** (эффекты Discord) — общий ползунок 0–200 %, по умолчанию 100 %, сохраняется. Новые 100 % равны прежним 8 % фактического уровня, 200 % — прежним 16 %; старое сохранённое значение `8` мигрирует без изменения слышимой громкости. Ползунок регулирует все эффекты Discord, включая отдельный Echo-хвост, в дополнение к общей выходной громкости; не меняет уровень микрофонных эффектов. Переход 10 мс, при 0 % Discord замолкает. Принадлежность источнику передаётся вместе с каждым отсчётом через выходную очередь, поэтому громкость не переключается раньше самого звука.

Проверка захвата без NVIDIA и без вывода: `bin\mic_check.exe --discord-capture`.

Если незавершённое обновление или откат обнаруживает отсутствие core/runtime либо TAG-драйвера, после проверки файлов комплекта открывается интерфейс для завершения установки. Это позволяет скачать runtime и установить драйвер, даже когда виртуальный микрофон ещё не готов. При наличии core и драйвера проверка готовности TAG остаётся обязательной; переход со старой 0.2.5 всегда проверяет живое устройство. Если после сбоя через Setup установлена другая версия, программа проверяет её полный пакет и подпись релиза (из кэша либо с GitHub), хеши установленного UI/хоста и метаданные; только затем сохраняет и завершает старый журнал, вместо отката переустановки. При отсутствии подписи или полного пакета проверка останавливается с ошибкой.

### Логи

При аварийном завершении интерфейса паника Rust (версия, место и стек) записывается в `%APPDATA%\Mic Noize\Logs\rust-ui-panic.log`.

Страница «Логи» (Настройки → «Логи и отчёт») собирает один текстовый отчёт: версия, видеокарта и её архитектура, драйвер NVIDIA, Windows, состояние движка, выход, прослушивание, текущий статус и последние строки `results/app.log` (40), `sessions.log`, `tag-host.log`, `tag-headphones.log`, `nvafx.log` с временем изменения каждого файла. Повторы подряд схлопываются в `(xN)`, путь профиля заменён на `%USERPROFILE%`. «Копировать всё» пересобирает отчёт и кладёт его в буфер обмена, «Открыть папку» открывает `results`. `app.log` пишет UI: запуск с GPU и каждое новое сообщение строки статуса с UTC-временем (обратный отсчёт перезапуска не дублируется); больше 512 КБ — остаётся новая половина. `nvafx.log` — ошибки NVIDIA SDK (`NvAFX_InitializeLogger`, уровень ERROR, только при ASCII-пути). `tag-host.log` содержит UTC-время; предыдущий файл после ротации — `tag-host.previous.log`.

### Прослушивание

**Слышать весь голос** — кнопка или сохраняемый глобальный хоткей включает прослушивание готового виртуального микрофона на устройстве вывода Windows (в голосе уже учтены NVIDIA, RVC, pitch и boost). Работает для TAG, в том числе без Discord. Задержка основного тракта плюс локальное воспроизведение — используйте наушники. Виртуальные выходы CABLE / VoiceMeeter / Broadcast для прослушивания заблокированы от петли. Ошибка прослушивания не останавливает шумодав; при ошибке движка или выходе оно выключается. Если Windows инвалидирует устройство вывода (`AUDCLNT_E_DEVICE_INVALIDATED`: наушники переподключены, сменён выход по умолчанию или формат), прослушивание переоткрывается на текущем выходе через 0,5 с, до 20 попыток подряд.

**Слышать эффекты** (`[effects] monitor_effects`, по умолчанию включено; с 0.4.14 включается один раз и у прежних установок, дальше выбор сохраняется) воспроизводит pitch, скорость, реверс, преобразованный RVC, повтор по хоткею и плитки «Последние записи»; **Слышать усиление** (`monitor_boost`, по умолчанию выключено) — усиление/перегрузку; **Слышать звуки в наушниках** на вкладке саундпада и **Слышать самому** в Студии — один общий переключатель (`[soundpad] monitor`) для звуков саундпада и трека Студии. Можно включить любую группу или все; совмещённые эффекты слышны при выборе любой группы. Настройки общие для микрофона и Discord; повтор по хоткею сохраняет категории записанных сэмплов (усиление в них не попадает), а плитки последних записей слышны и через галку звуков саундпада. При двух включённых галках плитка не удваивается. Полное прослушивание имеет приоритет.

## Саундпад

Вкладка **Саундпад** проигрывает звуки из выбранной папки поверх голоса в виртуальный микрофон. **Выбрать папку** назначает хранилище (`mp3`, `wav`, `ogg`, `m4a`; вложенные папки не читаются), **Добавить звуки** копирует выбранные файлы в эту папку (одноимённые пропускаются), **Обновить** перечитывает её. Список фильтруется полем поиска и сортируется: **По имени**, **С хоткеем сверху** (назначенные звуки первыми, в порядке клавиш), **Недавно игравшие** (по последнему запуску из списка или хоткеем; время сохраняется), **Новые файлы** (по дате файла). У каждой строки — запуск/стоп кликом или Enter, собственная громкость 0–200 % и хоткей. Ползунок громкости строки показан при наведении, при клавиатурном фокусе или если громкость не 100 %. Внизу страницы — панель «сейчас играет» и общие настройки: стоп-хоткей, общая громкость, выравнивание и «в наушниках». Список живёт в собственной прокрутке под закреплённой панелью; строятся только строки рядом с видимой областью и отдельно строка с клавиатурным фокусом. Расстояние до выбранного трека не увеличивает число создаваемых строк; пропуски сохраняют высоту списка. При переходе в короткий раздел или сужении поиска звуки остаются видимыми, даже если прежнее положение прокрутки было ниже нового списка. При прокрутке строки перерисовываются целыми полосами, без отдельных проходов для каждой надписи и ползунка. Плавная прокрутка обновляется по кадрам окна с учётом прошедшего времени, без отдельного таймера ожидания на каждый шаг; после остановки анимации подписка на кадры отключается.

Слева — **разделы**: «Все звуки», затем автоматические группы по повторяющемуся началу имени до « - » (`danya - …`, `des - …`; группа появляется от двух файлов, сортировка по размеру), затем свои разделы. **+ Раздел** создаёт раздел (имя вводится сразу, Enter сохраняет; двоеточие, `|` и табуляция вырезаются); выбранный свой раздел можно переименовать и удалить. Звук добавляется в свой раздел перетаскиванием за ≡ в начале строки на имя раздела; × в строке выбранного раздела убирает его оттуда. Разделы хранятся по именам файлов (`[soundpad] sections`), так что перечитывание папки их не теряет. Общая громкость 0–200 % умножается на громкость звука: новые 100 % соответствуют прежним 20 % (физический gain 0,04, около −28 дБ), 200 % — прежним 40 % (gain 0,08). Старые сохранённые 20 % автоматически отображаются как 100 % без изменения слышимого уровня; прежние значения выше 40 % ограничиваются новым максимумом 200 %. «Остановить всё» — хоткей и кнопка.

**Выравнивать громкость** (по умолчанию включено) приводит клипы саундпада к общему уровню, не трогая файлы. При загрузке звук измеряется по BS.1770 (LUFS интегральной громкости уже сведённого моно-сигнала, который и звучит; для стерео-файла число примерно на 3 дБ ниже «стерео-LUFS») и умножается на поправку: громче −12 LUFS приглушается до −12, тише −18 поднимается до −18, внутри окна не меняется. Подъём ограничен +12 дБ и пиком −1 dBFS, поэтому тихий клип с резкими пиками может остаться тише окна; приглушение не ограничено. Громкость строки 0–200 % и общая громкость работают поверх выравнивания; громкие клипы могут стать тише прежнего, это компенсируется общей громкостью. Окно задаётся `norm_min`/`norm_max` в `[soundpad]` (−40…−5; перевёрнутая пара даёт значения по умолчанию); `settings.ini` править при закрытом приложении, иначе сохранение перезапишет правку. Плитки «Последние записи» это выравнивание обходят; скопированный в библиотеку саундпада WAV обрабатывается как обычный звук. Переключение галки останавливает играющий клип и перезагружает библиотеку: звуки с хоткеями декодируются заново сразу, остальные при следующем запуске.

Хоткей звука: нажатие играет клип с начала, повторное нажатие того же хоткея останавливает, другой звук заменяет текущий (играет один клип за раз), быстрое двойное нажатие (до 170 мс) перезапускает с начала. Остановка и замена затухают 5 мс. Хоткей назначается прямо на кнопке: клик, нажатие клавиши (можно с Ctrl/Alt/Shift или боковой кнопкой мыши) — и готово; занятое сочетание показывается красным на той же кнопке и ожидание продолжается, повторный клик или Esc отменяет, × рядом убирает назначение. Так же работают все кнопки хоткеев на вкладке «Микрофон». Хоткеи звуков используют ту же схему клавиш и модификаторов, что и эффекты, не могут совпадать с ними и друг с другом, действуют только при работающей обработке и не в Mute; Mute остаётся последним. Звук не проходит через NVIDIA, RVC, pitch, фразы, усиление и громкость Discord: он подмешивается после эффектов в TAG и WASAPI одинаково. Полное прослушивание слышит его как часть голоса; «Слышать эффекты» и «Слышать усиление» — нет, для обычного звука есть «Слышать звуки в наушниках»: под галкой видно устройство вывода монитора и уровень, который он реально воспроизводит («тишина» / dBFS), либо причину, почему он не работает.

Клипы декодируются в UI (symphonia) в 48 кГц моно с линейной передискретизацией и живут в памяти движка (~190 КБ на секунду); длиннее 5 минут обрезаются. Звуки с хоткеем загружаются при запуске и назначении, остальные — при первом запуске из списка (кнопка показывает «загрузка…», ошибка декодирования остаётся в строке). Перечитывание папки выгружает все клипы и сохраняет хоткеи и громкости по имени файла.

## Студия

Вкладка **Студия** собирает короткий трек из четырёх тактов: в каждом 16 шагов, по вертикали четыре октавы C2–B5. Сетка прокручивается отдельно от кнопок управления и открывается в районе C4. Масштаб нот 50–150 % меняет высоту строк, чтобы видеть больше нот или редактировать крупнее. С клавиатуры Tab ставит фокус на сетку, стрелки двигают его между нотами и шагами, Enter или пробел переключает ноту. Выберите звук слева: ЛКМ ставит ноту, удержание и движение по строке растягивает её на несколько шагов, движение назад сокращает; ПКМ и движение с зажатой кнопкой стирают ноты. Короткий сэмпл в протянутой ноте повторяется не чаще одного раза за шаг BPM, чтобы не превращаться в жужжание; конец сглаживается. Оранжевая нота принадлежит выбранному звуку, серая — другому. Кнопки тактов переключают видимую часть, BPM задаётся от 60 до 200 с шагом 1. Проект (BPM, длительности нот, луп, масштаб и громкость) автоматически сохраняется в `[studio]` файла `settings.ini`.
Оранжевая линия показывает текущую позицию трека и переходит к следующему такту при воспроизведении. Широкую метку с номером шага над сеткой можно захватить и протянуть по линейке для перемотки; клик по любому номеру ставит курсор для следующего запуска. На линейку можно перейти клавишей Tab и двигать курсор стрелками. Перемотка работающего трека сглаживается спадом и нарастанием по 5 мс и действует только на трек Студии. Выбранный вручную такт остаётся на экране во время воспроизведения; запуск и перемотка снова ведут сетку за линией. Повторное нажатие «Играть в Discord» запускает трек заново с курсора; для остановки есть «Стоп». Воспроизведение требует запущенного виртуального микрофона.
Полоса «Луп» под тактами показывает весь трек. Включение переключателя запускает текущий трек, если виртуальный микрофон работает и есть ноты; после рисования или стирания нот звучание обновляется при отпускании кнопки мыши. Перетащите ближайший край полосы, чтобы задать начало и конец; ПКМ по полосе сразу ставит начало. Кнопки «От» и «До» берут соответствующую границу из положения курсора; с клавиатуры границы меняются стрелками. При достижении конца звук сразу возвращается к началу внутри аудиодвижка без ожидания кадра интерфейса, с коротким сглаживанием шва. «Стоп» останавливает воспроизведение и выключает луп, сохраняя границы. Экспорт WAV с включённым лупом сохраняет один выбранный цикл. Если луп выключен, трек доигрывает четыре такта и останавливается.
При прокрутке сетка создаёт кнопки только для видимых нот и ближайших строк; весь диапазон C2–B5 остаётся доступен. Свёрнутое окно не запускает для сетки отдельные кадры или таймеры.

**Записать звук** захватывает обработанный микрофон до выбора источника Discord, максимум 20 секунд; повторная кнопка завершает запись. Нужен работающий микрофон без Mute. Записи сохраняются как WAV в `%APPDATA%\Mic Noize\Студия\Звуки`; **Добавить файлы** копирует туда WAV/MP3/OGG/M4A. Кнопка × рядом с каждым звуком после подтверждения убирает его и его ноты; сам файл перемещается в `%APPDATA%\Mic Noize\Студия\Удалённые`. C4 играет сэмпл с исходной высотой; другие ноты меняют высоту без ускорения файла и изменения его длительности. При сборке используются первые 20 секунд каждого файла и не более 32 разных файлов в треке. Сборка происходит вне аудиопотока; пик тихого трека поднимается с ограничением усиления 18 дБ. Громкость «Трек» 0–200 % задаёт долю от настроенной на вкладке «Эффекты» громкости Discord: при 100 % у Студии тот же выверенный коэффициент, что у эффектов. Изменение обоих регуляторов сразу влияет на воспроизведение; тот же уровень пишется в WAV и слышен через «Слышать самому». Громкость саундпада не меняется. **Играть в Discord** подмешивает собранный трек поверх голоса через существующий выход TAG или WASAPI; **Стоп** останавливает его. Финальный Mute действует и на трек. **Сохранить WAV** пишет файл в `%APPDATA%\Mic Noize\Студия\Треки`. Для передачи через Discord выберите виртуальный микрофон Mic Noize в настройках Discord вручную.
Переключатель **Слышать самому** позволяет слушать трек через физические наушники при запущенной обработке микрофона. Он общий с переключателем **в наушниках** на вкладке «Саундпад» и не меняет отправку трека в Discord.

## RVC (Voice Changer)

На странице **Смена голоса** в блоке «Где скачать голос» есть кнопки [Voice Models](https://voice-models.com/) (каталог голосов и персонажей) и [Hugging Face](https://huggingface.co/models?other=rvc) (фильтр RVC). Они открывают сайт в браузере по умолчанию и доступны даже без установленного RVC runtime; клавиатурой — Tab, Enter или Space. Скачайте экспортированную модель RVC v1/v2 `.pth` и, при наличии, её `.index`; ZIP сначала распакуйте, затем нажмите «Импорт модели». Импорт становится доступен после установки runtime.

Сверху находятся включение и модель (каталоги, импорт, переименование, удаление), ниже две карточки рядом — «Тон модели» и «Тонкая настройка» (индекс, вход модели, блок аудио, обновление списка; раскрывается кнопкой «Показать»). В небольшом окне доступна прокрутка.

Страница **Смена голоса** выбирает импортированный слот VCClient из `%APPDATA%\Mic Noize\Components\vendor\vcclient-2.1.4-alpha\dist\main\model_dir\<слот>` (`params.json` и `.pth`/`.onnx`). Dev-сборка использует каталог `vendor` репозитория. Параметры: тон модели −24…+24 полутонов, влияние `.index` 0–100 % (без индексного файла эффекта нет), усиление входа модели 50–300 %, блок 100/150/200/300/500 мс (по умолчанию 200). Сохраняются в `[rvc]` и применяются при следующем запросе. Это отдельный тон модели, не обычный pitch-хоткей; `protect_ratio` эта сборка pipeline не использует.

**Задержка фиксированная: блок + 200 мс** (при 200 мс — ~400 мс), не зависит от лагов модели и не растёт со временем. Первые «блок + 200 мс» после включения, смены настроек или Mute — тишина. Опоздавший звук отбрасывается; если модель не успевает или сервер не отвечает — **тишина, а не обычный голос** (статус «Модель не успевает · пауза»). RVC обрабатывает только микрофон, Discord проходит без модели; Discord-хоткеи не выключают RVC для вашего голоса. Pitch, фразы, повтор и прослушивание работают с уже преобразованным голосом. Mute остаётся последним.

HTTP работает в отдельном потоке. Холодный запуск включает прогрев. Выключение RVC сразу завершает принадлежащее приложению дерево сервера (ожидание ограничено 2 с на этап, ошибка показывается в UI и пишется в `results/rvc-stop-error.log`); при выключенном RVC сервер не запускается, повторное включение требует холодной загрузки. Если сервер упал, UI выключает RVC сам (~250 мс) и обычный голос возвращается; зависший сервер даёт тишину до выключения. Выход из UI также завершает сервер. Абсолютный нулевой расход памяти не заявляется.

**Импорт модели**: выбор одной экспортированной RVC v1/v2 `.pth` и необязательного `.index` (Ctrl + щелчок). Импорт проверяет формат весов на CPU (`weights_only=True`), параметры и размерность индекса, копирует файлы в новый свободный слот и создаёт `params.json`. Исходники и существующие слоты не перезаписываются. Тренировочные checkpoint, legacy pickle/TAR и нестандартные архитектуры не поддерживаются. При выключенном RVC новая модель выбирается; при работающем текущий голос остаётся. Модель можно переименовать в списке; удаление доступно только при выключенном RVC, требует второго подтверждающего нажатия и удаляет весь каталог слота. Старая установка MMVCServerSIO 1.5.3 не используется.

FAISS в установленном VCClient использует `torch/lib/libiomp5md.dll` (исправление конфликта OpenMP: `src/rvc_openmp_fix.py`, оригиналы в `.tmp/rvc-openmp-originals`); после замены VCClient исправление нужно повторить. Сайдкар пересобирается PyInstaller (Python 3.10) при изменении `src/vcclient_server.py` или `src/rvc_import.py`; установленный — `vendor/vcclient-2.1.4-alpha/dist/main/mnr_vcclient_server.exe`.

## Наушники

Если хост отказал наушникам (на новой установке подписанный demo-драйвер занят своими двумя стандартными линиями и микрофоном Mic Noize, места для линии наушников нет), панель объясняет это и даёт кнопку «Освободить место»: она открывает «Восстановить устройство» в настройках с уже включённым переносом линий, запуск по-прежнему по подтверждению. Ошибки наушников пишутся в `app.log`. Панель **«Что слышите вы»** (шестерёнка у наушников на странице «Шумодав») — отдельный выход для стримов: независимые запуск/остановка, физический выход, шумодав NVIDIA v2 (0–200 %; выше 100 % — эксперимент, предупреждение появляется только тогда; при снятой галке «Шумодав NVIDIA» маршрут «Без обработки», и ползунок силы бледнеет, оставаясь редактируемым; галка стоит заголовком этого ползунка и переключается на ходу — работающая сессия переоткрывается в новом режиме), громкость 0–100 %, тон −12…+12 полутонов и **Реверс** (постоянный: куски по 200 мс с шагом 100 мс играют задом наперёд со сглаженными стыками; +200 мс задержки, пока галка включена). Отдельной кнопки Mute нет. Устройство выбирается в карточке «Наушники», оранжевая точка на шестерёнке показывает, что обработка или изменения звука включены. Настройки — в `[headphones]`; запуск всегда ручной. Выберите физические наушники и нажмите **Включить**, затем в микшере Windows направьте браузер в **Mic Noize Headphones (Thin Audio Gateway)**. После остановки верните выход браузера на физические наушники: виртуальное устройство отключается. Системный выход и настройки Discord не меняются.

Тракт: TAG render → отдельный NVIDIA denoiser на каждый канал → тон → ограниченная стереоочередь → громкость/Mute → WASAPI наушников. При отключённом NVIDIA работает сухой стереотракт. Режим NVIDIA и устройство меняются после остановки. Фильтр предназначен для речи: музыка и атмосфера стрима могут подавляться. Задержка включает обработку и буфер; синхронность видео/аудио не проверена. При выключенном разделе потоки завершены, модели освобождены; хоткеи микрофона не управляют наушниками. Дополнительная CPU/GPU-нагрузка не измерена. Виртуальные выходы запрещены как приёмник (защита от петли). После потери запросов наушников на 2 с их линия в хосте закрывается; микрофон продолжает обслуживаться.

## Настройки

Страница «Настройки» сверху вниз: «Микрофон и выход» (микрофон, выход, модель и буфер, строкой ниже состояние виртуального микрофона с кнопками «Восстановить устройство» и «Обновить устройства»), затем рядом «Приложение» (автозапуск с Windows, пиксельный переход, волна ползунков) и «Обновления» (проверка и предпросмотр анимации и карточки), внизу «Диагностика» с цифрами обработки, «Логи и отчёт» и «Выход из Mic Noize». Tab идёт в том же порядке.

`%APPDATA%\Mic Noize\settings.ini` (UTF-16, совместим с прежними версиями) сохраняется атомарно после короткой паузы изменений и при выходе; неизвестные ключи сохраняются. При первом запуске настройка копируется из старой установки или из корня dev-репозитория. Удержание и текущий Mute не сохраняются; автозапуск хоста хранится в реестре.

- `[audio]`: `input`, `output` (`TAG` или id устройства), `version` (1/2), `intensity`, `alternate_intensity` (0–200), `buffer_ms` (10–80, default 40), `period_ms` (2–20, default 5), `cuda_graphs` (−1 штатно / 0 / 1).
- `[effects]`: `boost`, `overload`, `pitch`, `formant`, `slow_speed`, `fast_speed`, `echo_delay_ms`, `echo_repeats`, `echo_decay`, `echo_level`, `stutter_ms`, `tune_root`, `tune_scale`, `tune_speed_ms`, `tune_strength`, `discord_volume`, `discord_volume_scale`, `monitor_effects`, `monitor_boost`, `rvc_enabled`, хоткеи `*_key` (код клавиши + модификаторы × 256), `replay_key` (default Ctrl+F8), `monitor_key`, `noise_key`.
- `[rvc]`: `slot`, `pitch`, `index`, `chunk_ms`, `gain`. `[headphones]`: `output`, `denoise`, `intensity`, `volume`, `pitch`. `[ui] tray_hint`.
- `[soundpad]`: `folder`, `volume_display` (общая громкость в интерфейсе, 0–200), `volume` (прежняя шкала для безопасного отката), `monitor` (0/1), `normalize` (0/1, по умолчанию 1), `norm_min`/`norm_max` (окно выравнивания, LUFS, по умолчанию −18/−12, вручную), `stop_key`, `sort` (0 имя, 1 хоткей, 2 недавние, 3 новые), `sections` (`имя:файл|файл` через табуляцию), `sounds` — записи `хоткей:громкость:последний запуск (unix-секунды):имя файла` через табуляцию только для звуков с хоткеем, громкостью ≠ 100 % или запуском.

## Проверки

Без NVIDIA:

```powershell
.\verify.ps1                                  # пересборка проверок, CTest, Rust-тесты, Clippy
.\bin\effects_check.exe                       # DSP: bypass, эффекты, фразы, реверс, повтор, RVC playout
.\bin\bridge_check.exe                        # C ABI, ошибки, контролы, стек TAG, dry bypass RVC
.\bin\mic_check.exe --self-test               # очереди, дрейф, часы TAG
.\scripts\check-asan.ps1                      # те же три проверки под AddressSanitizer, сборка в build\asan
.\bin\MicNoize.exe --ui-benchmark --ui-snapshot "$PWD\results\ui.png"
```

QA-флаги UI: `--ui-settings`, `--ui-logs`, `--ui-rvc`, `--ui-headphones`, `--ui-small`, `--ui-scale 2` с `--ui-snapshot`; `--ui-benchmark` без снимка открывает, закрывает в трей и повторно открывает окно. Запускайте при закрытом обычном экземпляре. `--start-tray` запускает без окна.

С железом (перед GPU-тестами проверьте свободную VRAM, оставляйте 2–4 ГБ; индексы устройств меняются — сверяйте через `--list`):

```powershell
.\bin\mic_check.exe --list
.\bin\mic_check.exe --smoke INPUT_INDEX TAG 60 2 40          # реальный микрофон → NVIDIA → TAG, 60 с
.\bin\mic_check.exe --smoke-phrases INPUT_INDEX TAG 14 2 40  # фразы обеих скоростей и сброс через Mute
.\bin\mic_check.exe --monitor-check INPUT_INDEX TAG          # прослушивание, Mute, остановка
.\bin\mic_check.exe --persistent-tag INPUT_INDEX             # тот же endpoint через два жизненных цикла движка
.\bin\mic_check.exe --lifecycle-tag INPUT_INDEX              # отсутствующий вход, 12 подключений, 48k/44.1k
.\bin\mic_check.exe --tag-reconnect INPUT_INDEX              # стойла 120/400 мс переживаются без остановки
.\bin\mic_check.exe --discord-capture                        # захват Discord без вывода
.\bin\mic_check.exe --headphones-check OUTPUT_INDEX 0|1      # стерео-тракт наушников, сухой / NVIDIA
.\bin\mic_check.exe --rvc-check                              # RvcClient против запущенного сайдкара
python .\src\rvc_check.py                                    # HTTP-контракт сайдкара
python .\src\rvc_import_check.py                             # импорт модели (CPU, из .tmp\pyi310-venv)
```

`--smoke` при выборе физического выхода воспроизводит обработанный микрофон на нём. Ненулевой код завершения означает ошибку, отсутствие обработки или пропуски. Замеры задержки (`--record-pair`, `--record-routes`, `--probe-cable`, `analyze-latency.py`) и A/B CUDA Graphs (`--bench-afx`, `analyze-afx.py`) описаны в CHANGELOG; они требуют NumPy в локальной `.venv` и частично VB-CABLE, который удалён. Только `--record-pair`/`--record-routes` сохраняют локальные аудиопакеты; обычная работа и smoke-тесты не записывают звук.

Диагностика: `run_max_ms` — `NvAFX_Run`, `reset_max_ms` — `NvAFX_Reset`; `gaps`/`underruns` — нехватка готового звука, `drops` — сброс переполненной очереди, `TAG_gaps` — счётчики драйвера, `late_ticks` — опоздания хоста, `reconnects` — переподключения к TAG-хосту, `runs_over_5ms`/`runs_over_10ms` — сколько 10-мс блоков `NvAFX_Run` обрабатывал дольше 5/10 мс (отличает единичный пик от постоянной перегрузки), `run_max_at_s` — секунда сеанса, на которой был максимум, `failed_at` — UTC-время сбоя (строка пишется при следующей остановке, иногда намного позже). После корректной остановки движка итог сеанса дописывается в `results/sessions.log` (без записи голоса); принудительно убитый процесс и старт, упавший до запуска потоков, строки не оставляют. `mic_check --bench-afx <pcm> <сек> <graphs> <csv> [churn]` меряет каждый блок NVIDIA офлайн; `churn` добавляет смену силы и `reset` как в реальном сеансе. `run-tag.ps1` запускает консольный прототип `mic_tag.exe` (не одновременно с UI); `run-sample.ps1 -Version 1|2` — официальный файловый пример NVIDIA после `build.ps1 -Samples`.

## Ограничения и что не проверено человеком

- Субъективное звучание pitch/насыщения/RVC на вашей речи в Discord, реальные игровые хоткеи, физическое извлечение USB, блокировка/сон и перезапуск Explorer — код есть, физическая проверка не проводилась. FPS не измерялся. Настройки Discord автоматически не менялись; его AGC может уменьшать заметность boost.
- Denoiser v1 не считается стабильным режимом под нагрузкой; причина редких длинных вызовов NVIDIA (до 224 мс) не установлена, запас 40 мс их не покрывает.
- Стойло аудиопотока дольше 2 с останавливает обработку (watchdog микрофона); восстановление после сна/USB — вручную через «Обновить устройства».
- Носители: TAG demo, GPL Rubber Band и NVIDIA-модели делают сборку непригодной к распространению без отдельного решения по лицензиям.

Личная локальная сборка. NVIDIA и TAG файлы не включаются в публичную поставку проекта; `vendor` содержит проприетарные компоненты, не собственный код.
