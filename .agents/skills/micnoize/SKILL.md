# Mic Noize

Resolve all source paths below from the project root (the folder containing `AGENTS.md` and `CMakeLists.txt`). Default location: `D:\Projects\Audio\MicNoiseReducer`.

The product and internal app name is **Mic Noize**. Installed program files live under `%LOCALAPPDATA%\MicNoize`; persistent settings and runtime live under `%APPDATA%\Mic Noize`. `MNR` means **Mic Noize Runtime**: preserve the `mnr_*` ABI, `MNR_*` environment variables, `/mnr/` routes, sidecar name and frozen TAG IPC `.v1` layout. Current audio/status IPC uses separate `.v2` objects.

## Preserve these contracts

- TAG line IDs persist as `MicrophoneLineId`/`HeadphoneLineId` DWORDs under `HKCU\Software\MicNoize\TAG\4d699d4a-65a5-40ec-9875-8e6d5fc01e0c`, read/written before the audio loop. First allocation starts at 3 because the signed demo driver restores defaults 1/2 on boot. A saved-ID conflict fails explicitly; never silently pick a different ID. Build 06 host restart and actual Windows reboot preserved line 3 and its exact endpoint; startup/name/100%/shared-only passed on this machine. Legacy own lines 1/2 need explicit migration.
- Current stack: Iced 0.14 with CPU tiny-skia (`iced_tiny_skia` `geometry` for slanted slider paths in `ui/src/tacho.rs`; its damage tracking treats uncached geometry as always changed and places custom text at its anchor, so reuse `Painted` and `put` there); C++20 static engine via C ABI; NVIDIA SDK 3.0.0.51, Ampere denoiser v1/v2; Rubber Band 4.0.0 LiveShifter. Consult pinned manifests before dependency work. NVIDIA assets are under `vendor/nvidia-afx-3.0.0`, hashes in `nvidia-assets.sha256`.
- Main flow: 48 kHz mono / 480-sample denoised/RVC blocks → raw effect input plus gated live/background voice (pre-gate meter, -72 dB exact bypass) → source-specific stutter → shared Rubber Band tone/formants/AutoTune (keep the shifter running through unvoiced input while AutoTune is held) → phrase/boost → echo → gate unmodified microphone samples → replay/soundpad → bounded output queue → Mute → TAG or WASAPI. Effect captures/playback bypass the gate; RVC alone remains gated voice. DSP-only `ModifiedVoice` must become `ModifiedEffects` before capture/queuing; phrase resets still discard live recording marks. Keep allocation, file I/O and model work out of the Windows render loop. Inactive effects must add no permanent latency or replay an old tail.
- `RoutedSample` carries Discord identity, separate microphone/Discord echo stems, per-sample effect category bits (1 other effects, 2 boost; replay preserves them) and effect epoch through the queue. Apply Discord gain only to its corresponding output and echo samples, not according to the current hotkey. Both output paths use `OutputEffects`; boost is applied before the queue, and routed microphone background stays separate from Discord gain and effects-only monitoring. `LastEffect` keeps one bounded shared replay slot in DSP, including echo tails without returned dry voice. Independent other-effect/boost monitoring (C ABI monitor modes 2/3/4; full voice is 1) taps final TAG/WASAPI output through a bounded SPSC queue; preserve sample flags, epoch rejection and Mute. Full monitoring takes priority over effects-only monitoring on the same Monitor instance.
- Desktop/Discord names in code refer to Windows **process loopback** of native Discord/Canary/PTB. This source bypasses NVIDIA. Source selection remains fixed during a phrase; do not leak the microphone or an old pitch tail across switches.
- RVC (`RvcClient` + `RvcPlayout`) runs on the microphone right after NVIDIA, before the Discord source switch, pitch and phrases: the converted voice is what those effects and the Discord-hold background mix receive. It is a fixed delay line of `chunk + rvcSlack` (200 ms): both rings carry generation-tagged samples with aligned indices, the worker emits exactly one output sample per consumed input (zeros for skipped or failed chunks), late audio is dropped, missing audio is **silence**, never the dry voice. Only the DSP thread trims `output_`. `effects_check` covers the playout; `mic_check --rvc-check` needs the live sidecar.
- There are 21 binding slots: the original 13 keep their indices (five microphone effects, five Discord effects, monitor, replay, alternate noise hold); slots 13/14/16 are microphone Echo/Stutter/AutoTune, slots 17/18/20 their Discord versions. Retired Granular slots 15/19 are ignored; keep their ABI positions and reserved grain option fields. Legacy `mnr_bindings` 12/13-key calls remain supported. Soundpad clip keys are a separate list (`mnr_sound_bindings`, id 0 = stop) polled by the same shell loop with the same eligibility; the Rust controller owns duplicate rejection across both sets. Clips bypass every effect and Discord gain (`RoutedSample.sound`, `OutputEffects` `sound` parameter) and never touch files in the DSP thread. Recent-recording tiles carry a per-sample `RoutedSample.recording` flag: the monitor includes them for either the effects or sound checkbox, exactly once when both are on; ordinary soundpad clips remain sound-only. Exact modifiers, duplicate rejection, fresh-press latches and the 250 ms stale-state cutoff are intentional. Preserve resets on Mute/Stop/error/client loss/lock/sleep/rebinding.
- Speed is record-while-held with live microphone passthrough, play-on-release, with pitch coupled to speed. Reverse differs by source: microphone passes the normal phrase; Discord recording sends no normal phrase to the virtual microphone. Both then wait 150 ms before reverse playback. Preserve the smoothed end and bounded phrase storage.
- Boost defaults to 167% and caps at 2000%; overload defaults off and is optional hard clipping, not stronger denoising. Discord effects share a saved 0–200% output control after boost/overload: displayed 100% is physical gain 0.08 and 200% is 0.16. It does not scale microphone samples. See README only for additional ranges and user behavior needed by the task.
- Microphone noise presets use `intensity` / `alternateIntensity`; slot 12 has its own `noiseHeldSample` with the existing epoch/250 ms freshness rules. The DSP selects strength before NVIDIA; no UI polling or model restart is involved. Both levels and the binding persist. Do not mix this hold into effect routing/replay flags.
- Without usable NVIDIA the DSP thread uses DeepFilterNet 3 on the CPU (`ui/src/cpu_denoise.rs`, registered via `mnr_set_cpu_denoiser`; +30 ms), else passes the voice through; never fail the session for a missing denoiser. `MNR_DENOISER=cpu` forces the CPU path. An input named RTX Voice / NVIDIA Broadcast is already denoised: state 4, no own denoiser (GTX 10xx route).
- NVIDIA TensorRT models are per GPU architecture: `gpuArch` (CUDA device 0) picks `models/<arch>`; the core ships Ampere, other architectures arrive as `models-<arch>` components. Never hardcode an architecture.
- Noise suppression above 100% is an experimental SDK request; acceptance and extra suppression are not established. No Speaker Focus or Broadcast-equivalence claims.
- A fresh PC has no TAG driver: the settings install button explicitly invokes `wdmdrvmgr.exe` with UAC after the core is present. Repair first tries health/restart and invokes that installer only when the user checks permission to reinstall; it can recreate an endpoint. Never run UAC automatically at startup or while recovering an interrupted repair. Auto-start waits for `driver_ready`. The host is bundled beside UI; the old core-host location is a migration fallback only. The shell also checks TAG API DLL presence before starting it.
- Device defaults must work on any machine: `devices(capture)` puts the Windows default communications endpoint first, and the controller falls back to it when no microphone is saved. A saved id still matches exactly or stays unselected.
- A downloaded update is announced above every page (`focus::UPDATE_BANNER`), not only in Настройки. Each page's Tab order is an explicit list in `key()`: a new button must be added there and to the activation match, or the keyboard cannot reach it.
- Telemetry and the "Отправить логи разработчику" button need `MNR_TELEMETRY_SECRET` at build time, so local builds send nothing by design. Logs travel as `error` events (`source: micnoize`), tails only.
- UI starts stopped; close hides to tray; explicit Exit stops the engine but leaves TAG host alive. Use `exit_ui()` for every Iced exit: it queues WM_QUIT to wake Winit 0.30.13 after a tray-only AboutToWait exit. The Windows regression is `scripts/check-tag-tray-exit.ps1` (UI must be closed; processing disabled). Unfocused/minimized/tray UI does not poll or animate meters; its lifecycle timer runs at 250 ms versus 50 ms for focused running UI. Native hotkey polling/heartbeat stays independent. Tray command polling (`ShellTick`) runs separately at 25 ms; do not put it behind state/device polling. Update animations force one damage pass through the invisible backdrop stamp. Removing the update colour key must retain `WS_EX_LAYERED` with opaque `LWA_ALPHA`; clearing that style discards the surface.
- Headphones are a separate opt-in stereo path: `Headphones` in `audio.cpp`, C ABI `mnr_headphone*`, and the headphones UI page. The same TAG host owns both lines (driver open is exclusive); `HeadphoneLink.v2` is separate from microphone `TagLink.v2`; never reinterpret old `.v1` mappings. Stop frees headphone models/threads and disconnects its endpoint. Preserve physical-output validation, stereo, bounded queues, final Mute and independent microphone controls. The demo TAG driver holds only three lines. `TagOutput` preserves unrelated lines. Explicit Repair consent (`ReplaceDefaultMicrophone`) permits removing only the identity-verified default capture line 1, including when the driver restores it at boot; repair preserves healthy own IDs and can migrate old own IDs 1/2. Capacity/identity errors require user action. Never delete other endpoints during startup/Refresh. Headphone reverse is `GrainReverse` (`effects.hpp`), adding latency only while on.
- TAG host supplies silence without a producer and owns endpoint persistence. IPC uses an acknowledged shared block, not another playback queue. The host drops a producer after 50 ms without data; `TagClient::write` then returns false once, re-registers and `tagLoop` re-primes (`Stats::tagReconnects`) — keep that path, never turn the first rejection back into a session failure. Host/IPC upgrades need coordinated compatibility handling, not a routine host restart workaround.
- TAG can forget the custom line on reboot while Windows keeps its endpoint unplugged. Reuse the unique `MicNoize Microphone` KS line or create it with `EpName="Mic Noize"`; never select an unrelated capture line as fallback. The host resolves the active endpoint by driver instance plus KS topology and publishes `TagEndpoint.v2` separately from audio IPC. Its control worker holds master/channels at 100% and clears system Mute even with UI closed; engine/monitor use its exact endpoint and compensation. The user chose shared-only WASAPI: the host disables exclusive access only on its bound endpoint using Windows' exclusive-control property (not in the public SDK), verifies readback on the control worker, and fails readiness on errors. Preserve the measured shared-mode compensation; exclusive gain parity is no longer a requirement. Recheck policy after endpoint recreation and on supported Windows versions. Never change Discord device settings automatically.

- Host startup uses a current-user interactive scheduled supervisor (`--scheduled`) and verified audio worker (`--worker={generation GUID}`); demand start always, login only when opted in. No time/battery/network/idle limit. Worker stalls trigger a 15-awake-second watchdog and a 60-second retry. Current logon, generation and shared three-retry budget persist in HKCU; a volatile minute recovery task covers loss of both processes and parent death during worker backoff. The supervisor publishes a separate heartbeat; the recovery task can stop only a verified stalled supervisor, preserving its healthy worker. Build 10 actual closed-UI suspension checks passed (parent 179.6 s, both 256.8 s), exact endpoint retained. Normal `--stop` cancels persisted recovery and late generations. Native Scheduler `RestartOnFailure` alone did not work on the tested Windows. Early worker ownership is published before endpoint initialization; process adoption verifies path/session/creation time/build/generation. `--direct` is the warned Scheduler fallback. Host/UI compatibility uses PE resource 101 (`tag_version.h`); stage hosts outside `bin` for coordinated replacement. Published-package migration passed on a copied installation; final Windows hardware acceptance remains open. Never describe the entire release as accepted.

## Implement and verify

1. Select the path above, inspect current code and make the requested change. For UI changes, follow the applicable taste skill while preserving the existing graphite/orange layout, keyboard focus and 100–200% scaling unless redesign is requested.
2. Read only the relevant section of [workflow.md](references/workflow.md) when building, testing or deploying. A C++ change must rebuild `mic_engine` before Cargo links it. Do not run the full bootstrap build against a live host for an ordinary edit.
3. Run the smallest existing checks that exercise the changed behavior. New non-trivial DSP needs a focused regression in the existing check executable. Verify shared output changes for both routes, neutral bypass, finite bounded samples and Mute.
4. If shipping an executable, follow the install sequence in the workflow. If changing only docs, validate paths and instructions without touching running audio.
5. Report what changed, what actually passed and any untested hardware/listening requirement. Update the relevant README section (behavior only) and add a dated CHANGELOG.md entry (checks, logs, limits) without appending a transcript.
